#### 1.2 修复 Hydration 错误 ✅
**时间**：2026-09-22  
**Commit**: `2657c1e`, `e4650c3`

**问题**：
- `AuditFilters` 组件在 `useEffect` 中读取 URL 参数
- 服务端渲染和客户端渲染不一致，触发 React hydration 错误

**解决方案**：
```typescript
// 服务端传递参数
export default async function LogsPage({ searchParams }: Props) {
  const params = await searchParams;
  return <AuditFilters initialFilters={params} />;
}

// 客户端组件直接使用 props，不再使用 useEffect 读 URL
```

**技术要点**：Next.js 14 App Router SSR 规范

```typescript
if (kpi.status === 'COMPLETED') {

  return items.reduce((sum, item) => sum + item.score * item.direction, 0);
}
```

## 🔍 技术亮点

### 1. Next.js 14 SSR 最佳实践
解决 Hydration 错误的标准方案：
- 服务端通过 `searchParams` 获取 URL 参数
- 通过 props 传递给客户端组件
- 避免客户端 `useEffect` 中读取 `window.location`

### 2. Prisma 关系查询优化
使用 `include` 减少 N+1 查询：
```typescript
const logs = await prisma.personalKpiActionLog.findMany({
  include: {
    personalKpi: { include: { user: true } }
  }
});
```

### 3. 适配器模式应用
- 6 种日志表统一映射为 `UnifiedAuditRecord`
- 各自定制 `objectName` 构造逻辑
- 查询服务无需关心具体实现

### 4. 状态机设计
KPI 汇总口径按状态分派：
- `COMPLETED`：读持久化字段（冻结历史）
- 其他状态：实时计算（应用新口径）

## 💡 工作心得

1. **SSR 规范很重要**：Next.js 14 的 hydration 错误需要从根源解决，不能靠 `suppressHydrationWarning` 掩盖。

2. **关系查询优化**：Prisma 的 `include` 能显著减少数据库查询次数，但要注意先定义好 schema 关系。

3. **适配器模式适合多数据源**：统一接口，各自实现，查询服务代码清晰易维护。

4. **状态机思维**：不同状态用不同逻辑，避免"一刀切"导致历史数据被污染。

5. **交接文档要详细**：包括问题分析、解决方案、部署指引、回滚方案，方便后续维护。
