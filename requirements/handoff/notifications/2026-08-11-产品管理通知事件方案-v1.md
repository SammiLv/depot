## 4. 一期事件清单（8 条）

### 4.1 定时扫描（SCHEDULE）— 3 条

| 事件码 | 中文名 | 触发条件 | 接收人 | 预设扫描 |
|--------|--------|----------|--------|----------|
| `quarterly_work.overdue` | 季度任务延期 | status ∉ {COMPLETED, CLOSED, DELAYED_COMPLETED} 且 `endMonth` < 当前月 | 负责人 + 组长 | 每周一 09:00 |
| `project.overdue` | 项目延期 | status ∉ {COMPLETED, CLOSED} 且 `endQuarter` 已过 | 负责人 + 组长 | 每周一 09:00 |
| `project.value_observation.pending` | 价值观测待填写 | status=COMPLETED 且 `valueJudgement=未观测` 超过 **N 天**（建议默认 7） | 负责人 + 部门主管 | 每周一 09:00 |

scanType 注册名（写入 `SCHEDULE_SCAN_REGISTRY`）：

- `quarterly_work_overdue` → `quarterly_work.overdue`
- `project_overdue` → `project.overdue`
- `project_value_observation_pending` → `project.value_observation.pending`

### 4.2 业务事件（EVENT）— 5 条

| 事件码 | 中文名 | 触发点（代码挂载） | 接收人 |
|--------|--------|-------------------|--------|
| `quarterly_work.assigned` | 季度任务负责人变更 | `createQuarterlyWork` / `updateQuarterlyWork`（`ownerId` 变化） | 新负责人 |
| `quarterly_work.status.changed` | 季度任务状态变更 | `updateQuarterlyWork`（`status` 变化） | 负责人 + 组长 |
| `project.assigned` | 项目负责人变更 | `createProject` / `updateProject`（`ownerId` 变化） | 新负责人 |
| `project.completed` | 项目已完成 | `updateProject` / status cascade → `COMPLETED` | 负责人 + 部门主管 |
| `project.value_judgement.changed` | 价值判断变更 | `updateProjectValue` / `createValueTrack` / `updateValueTrack` | 负责人；若 → `不达预期` 加组长/主管 |

**说明 — 项目完成：**

- 完成时 action 已将 `valueJudgement` 默认设为 `未观测`
- EVENT `project.completed` 提醒负责人/主管做价值观测；SCHEDULE `project.value_observation.pending` 扫逾期未填

## 5. 一期预设场景（5 条）

| # | 场景名称（建议） | 触发 | 接收人规则 |
|---|------------------|------|------------|
| 1 | 季度任务负责人变更通知 | EVENT / `quarterly_work.assigned` | SUBJECT_USER（新负责人） |
| 2 | 项目完成提醒价值观测 | EVENT / `project.completed` | SUBJECT_USER + DEPARTMENT_MANAGER |
| 3 | 价值判断不达预期提醒 | EVENT / `project.value_judgement.changed` | 条件：valueJudgement=不达预期 → 负责人 + 组长 + 主管 |
| 4 | 季度任务延期提醒 | SCHEDULE / `quarterly_work.overdue` | SUBJECT_USER + TEAM_LEADER_OF_SUBJECT |
| 5 | 项目价值观测待填写 | SCHEDULE / `project.value_observation.pending` | SUBJECT_USER + DEPARTMENT_MANAGER |

**一期明确不做：**

- 产品目标（ProductGoal）状态变更通知
- 季度工作审批（审批流未落地）
- 周更新待提交（`WeeklyWorkUpdate` 无 write）
- `todo.due_soon` 预置（见 §7）

```text
appUrl, targetId, targetType, title,
ownerId, ownerName, year, quarter,
status, previousStatus,
departmentOrgNodeId, departmentName
```

**分事件扩展：**

| 事件 | 额外字段 |
|------|----------|
| `quarterly_work.*` | workId, projectId, projectTitle, startMonth, endMonth |
| `project.*` | projectId, productGoalId, productGoalTitle, endQuarter, valueJudgement, previousValueJudgement, actualValue |
| `project.value_observation.pending` | daysSinceCompleted, completedAt |

**跳转建议：**

```text
{{appUrl}}/quarterly-work?year={{year}}&quarter={{quarter}}
```

（按 Tab 可扩展 query，实现时在模板中固定即可。）

## 7. 接收人 Resolver

一期**复用现有**，无需新增 resolver：

| Resolver | 用途 |
|----------|------|
| `SUBJECT_USER` | 负责人 / 新指派对象 |
| `TEAM_LEADER_OF_SUBJECT` | 负责人所在组组长 |
| `DEPARTMENT_MANAGER` | 部门主管 |
| `EXPLICIT_USERS` / `ROLE` | 管理员自定义 |

**关于 `todo.due_soon`：**

- 保留 registry 注册，**一期不新增预置**
- 推荐产品管理走 **SCHEDULE 直扫业务表**（与指标管理一致），不依赖 TodoItem
- 待审批 Todo 体系明确后，再决定是否联动 `todo_due`
