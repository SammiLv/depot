## 1. 范围与原则

- 模块：**指标管理**（侧边栏 `/annual-goals`）
- 事件码前缀：`annual_goal.*`
- 系统内通知类型：默认 **`GOAL_UPDATE`**（风险类场景可配置为 `TALENT_WARNING`，非强制）
- 审批流相关事件**不在本期**（业务未落地）
- 以下事件**不纳入**：方案生效、进度已更新、小组承接未完成（主管扫描）

---

## 2. 一期事件清单（6 条）

### 2.1 定时扫描（SCHEDULE）— 2 条

| 事件码 | 中文名 | 触发条件 | 接收人 | 预设扫描 |
|--------|--------|----------|--------|----------|
| `annual_goal.progress.weekly_pending` | 周进度未更新 | 当前季度内，小组承接的指标/元指标 `progressUpdatedAt` 超过 **N 天**（默认 7）未更新 | **仅指标责任人**（`responsibleUserId`） | 每周一 09:00 |
| `annual_goal.quarter_target.missing` | 季度目标未拆解 | 部门 ACTIVE 方案下，承接范围内的指标/元指标缺 Q1–Q4 或季度合计未覆盖 | **对应组长** + **对应指标责任人** | 每周一 09:00 |

scanType 注册名（实现时写入 `SCHEDULE_SCAN_REGISTRY`）：

- `annual_goal_weekly_progress_pending` → `annual_goal.progress.weekly_pending`
- `annual_goal_quarter_target_missing` → `annual_goal.quarter_target.missing`

### 2.2 业务事件（EVENT）— 4 条

| 事件码 | 中文名 | 触发点（代码挂载） | 接收人 |
|--------|--------|-------------------|--------|
| `annual_goal.target.changed` | 指标目标值变更 | 部门指标 / 元指标 / 季度目标 **`targetValue` 变更** | 有 `responsibleUserId` → **责任人**；**无责任人 → 部门主管** |
| `annual_goal.team.responsible_pending` | 小组指标待配置责任人 | 小组**新建指标承接**（`AnnualGoalMetricAssignment` create）且存在 **`responsibleUserId` 为空** 的承接项 | **该小组组长** |
| `annual_goal.risk.changed` | 风险状态变更 | 指标 / 元指标 / 季度目标 `riskStatus` 变为 **`SLIGHT_DELAY` 或 `RISK`**（相对原值变化） | 默认：**责任人**；无责任人 → **主管**（与目标值变更一致，场景可配置） |

**说明 — 风险状态变更：**

- 字段：`NORMAL` / `SLIGHT_DELAY` / `RISK` / `COMPLETED`
- 当前多为人工维护；通知用于「标为滞后/风险时提醒相关人」，非自动判定
- 变为 `COMPLETED` 或从风险降回 `NORMAL` 是否通知：**默认不通知**（仅升风险通知）

## 3. 一期预设场景（通知中心配置侧）

首期 seed / bootstrap **先配 5 条**（对应上表 6 个事件中的 5 个场景；`quarter_target.missing` 与 `progress.weekly_pending` 各 1 条，EVENT 各 1 条）：

| # | 场景名称（建议） | 触发 | 接收人规则 |
|---|------------------|------|------------|
| 1 | 周进度未更新提醒 | SCHEDULE / `annual_goal.progress.weekly_pending` | `METRIC_RESPONSIBLE`（或 EXPLICIT 映射责任人 resolver） |
| 2 | 季度目标未拆解提醒 | SCHEDULE / `annual_goal.quarter_target.missing` | 组长 + 责任人 |
| 3 | 指标目标值变更通知 | EVENT / `annual_goal.target.changed` | 责任人；无则主管 |
| 4 | 小组指标待配置责任人 | EVENT / `annual_goal.team.responsible_pending` | 承接小组组长 |
| 5 | 指标风险状态变更 | EVENT / `annual_goal.risk.changed` | 责任人；无则主管 |

**明确不做预设：**

- ~~小组承接未完成（主管扫描）~~
- ~~小组已承接指标（泛化承接通知）~~ — 由「待配置责任人」替代
- ~~方案已生效~~
- ~~进度已更新~~

## 4. Payload 字段（公共 + 分事件）

**公共：**

```text
planId, planName, year, departmentOrgNodeId, departmentName,
metricId, metricName, metricCode,
sourceMetricId, assignmentId, teamOrgNodeId, teamName,
quarter, targetId   // 跳转：/annual-goals?year={{year}}
```

**分事件补充：**

| 事件 | 额外字段 |
|------|----------|
| `progress.weekly_pending` | `responsibleUserId`, `responsibleUserName`, `daysSinceUpdate` |
| `quarter_target.missing` | `missingQuarters[]`, `responsibleUserId`, `teamOrgNodeId` |
| `target.changed` | `previousTargetValue`, `targetValue`, `unit`, `fieldScope`（metric/source/quarter） |
| `team.responsible_pending` | `assignmentCount`, `metricNames[]`, `teamOrgNodeId` |
| `risk.changed` | `previousRiskStatus`, `riskStatus`, `updaterId`, `updaterName` |

## 5. 接收人 Resolver（需新增）

在现有 `SUBJECT_USER` / `DEPARTMENT_MANAGER` / `TEAM_LEADER_OF_SUBJECT` 基础上，建议新增：

| Resolver | 含义 |
|----------|------|
| `METRIC_RESPONSIBLE` | payload 或 DB 中的 `responsibleUserId` |
| `TEAM_LEADERS_OF_TEAM` | 按 `teamOrgNodeId` 查 `TEAM_LEADER` |
| `PLAN_DEPARTMENT_MANAGERS` | 按 `departmentOrgNodeId` 查主管 |
| `METRIC_RESPONSIBLE_OR_DEPT_MANAGER` | 有责任人则责任人，否则主管（**目标值变更、风险变更默认**） |

## 7. 与 v2 草案差异摘要

| 项 | v2 | **v3（确认）** |
|----|-----|----------------|
| 小组承接未完成 → 主管 | 保留 | **删除** |
| 小组已承接 → 组长 | 保留 | **删除**，改为「待配置责任人」 |
| 小组待配置责任人 | 无 | **新增 EVENT** |
| 风险变更 | 待定 | **一期做** |
| 目标值变更无责任人 | 待确认 | **通知主管** |
| 首期预设条数 | 4~5 | **5 条**（2 SCHEDULE + 3 EVENT） |

## 8. 测试要点

1. 责任人周进度超 N 天 → 仅责任人收到提醒  
2. 缺季度拆解 → 组长 + 责任人各收到（同组多指标可 dedupe）  
3. 修改 targetValue → 责任人收到；清空责任人后修改 → 主管收到  
4. 新建承接且未填责任人 → 组长收到「待配置责任人」  
5. riskStatus 改为 RISK → 责任人/主管收到；改回 NORMAL 默认不发
