# 产品价值跟踪与首版完成度改造 — 实施交接

> 对应建设方案：`requirements/handoff/quarterly-work/2026-09-20-产品价值跟踪与需求首版完成度建设方案.md`
> 实施完成：2026-10-13，dev 环境已全量落地并走查。本文记录**最终口径**（多处已在走查中调整，与方案原文不同处以本文为准）。

---

## 1. 本次交付内容

1. 价值跟踪从"手动建记录"改为"任务制"：项目首次上线自动生成两次跟踪任务；
2. 新增「首版完成度」项目指标，按需求工作量统计；
3. 项目新增「是否开发项目」字段及状态流转矩阵；
4. 「未观测」更名为「待观测」；
5. 价值跟踪列表改为项目维度 + 可展开跟踪记录子列表；
6. 历史数据回填脚本。

## 2. 最终业务口径（与方案偏差已标注）

### 2.1 是否开发项目（needsDevelopment）

- **自动维护**：`开发项目 = 存在开发需求（未删除、非关闭）或 已上线`；
- 触发时机：需求新建/编辑（工作量、是否需开发、状态）/删除时随快照一起重算；已上线项目永为开发项目；
- 编辑弹窗手改会被自动规则覆盖；
- 历史回填：存在开发需求 或 launchedAt 非空 → 是。

### 2.2 项目状态流转矩阵

- 未启动 → 任意状态；
- 进行中 → 只能到已上线（开发项目）/ 已完成、已关闭（非开发项目）；
- 已上线 → 已完成、已关闭（不可回退）；
- 已完成、已关闭 → 终态锁死，无产品内回退通道；
- 非开发项目任何状态都没有「已上线」可选；已上线过的项目禁止改为非开发。

### 2.3 进入价值跟踪列表的条件

- 开发项目 或 有上线时间；**但从未上线的已完成/已关闭项目除外**；
- 季度过滤：未上线按规划周期匹配，已上线按 6 个月跟踪窗口与所选季度相交，逾期未填报继续显示；
- 「+ 新增」入口：已上线 且 记录不足两条 才显示。

### 2.4 跟踪任务

- 项目首次上线时自动生成第 1、第 2 两次任务（周期 = 上线日~+3月、+3月~+6月，截止 = 检查点+7 天，自然月月末钳制、支持跨年），幂等；
- 时间窗口**只做提醒**（未到期/待处理/逾期），不拦截填报；
- 每条记录只有「保存」，没有"完成/冻结"动作；项目级"已完成"状态由「编辑项目价值」弹窗手动维护；
- 新增弹窗的跟踪周期必选，已被占用的周期不可再选（服务端同样拦截），默认选中剩余周期；每项目最多两条记录；
- 已冻结（isFinal）记录不可编辑/删除（字段保留，当前 UI 不产生新的冻结）。

### 2.5 首版完成度

- 统计对象：项目下 `needsDevelopment=是`、未软删、非「关闭」的需求；
- **划分按需求完成时间**（偏差：方案原文为创建时间）：完成日 ≤ 上线日 → 首版；上线后完成或未完成 → 迭代；未上线项目全部计首版；
- `首版完成度 = 首版工作量 / (首版+迭代) × 100%`，保留 1 位小数；
- 缺工作量的需求不进合计；有缺失/无开发需求/总量为 0 → 显示「-」；
- **项目表快照实时自动重算**（唯一事实源，不可手工编辑）；跟踪记录快照 = 保存那一刻的实况（偏差：不排除宽限期新增，方案 §4.4 已废弃）；补录历史周期时按该周期检查点统计。

### 2.6 其他

- 跟踪状态：待观测/观测中/已完成（「未观测」已迁移）；价值判断只走下拉筛选，无状态卡片；
- 跟踪记录快照字段含当次的价值判断、实际收益（不随项目当前值变化）；
- 开发需求必须填工作量（表单+服务端）；跟踪记录填报时实际收益、价值判断必填，跟踪结果描述非必填；
- 上线时间修改受保护：已冻结禁止改；已有跟踪记录仅管理员可改并重算未冻结任务时间轴。

```

  quarterly-work-query.ts         列表/面板数据装配（范围、指标读取、需求构成明细）

src/app/(authenticated)/quarterly-work/content.tsx   价值跟踪页签（列表+子列表+两个弹窗）

```

测试：`pnpm test:quarterly-work`（30 个纯函数用例）。

## 5. 生产部署步骤（由生产会话执行）

1. `pnpm prisma migrate deploy --config db/prisma.config.ts`（5 个迁移，含数据回填 SQL）;
2. `pnpm prisma generate --config db/prisma.config.ts` 并重启服务；
3. 备份数据库后执行 `pnpm tsx scripts/backfill-value-track-periods.ts`（预检）→ 确认冲突清单 → `--apply`（回填历史记录周期、补齐开发项目的两次任务、重算全部项目快照）;
4. 冲突记录（同项目同周期多条）由业务确认合并后，再考虑加 `@@unique([projectId, trackingSequence])`。
