# **一、需求概述**

## **1.1 背景**

- 产品部管理工作台需要按小组规划年度产品目标、拆解项目与任务，并在执行过程中持续跟踪进展。
- 任务和项目超过计划周期后，需要在看板上自动进入「延期」列，并配合通知提醒，避免靠人工逐条核对。
- 项目上线后需要继续跟踪需求价值：工作量、其他成本、实际收益、跟踪状态、价值判断，以及历次跟踪日志。
- 模块数据对部门内成员公开可见；新增、编辑、删除按组织权限矩阵按能力授权，避免「能看不能管 / 能管越权」混在一起。

## **1.2 目标**

- 提供产品目标 → 项目 → 任务的完整维护闭环，支持卡片看板与列表两种展示。
- 按部门、小组、年、季度筛选工作数据；任务超期、项目超期自动归入延期列。
- 项目上线后进入需求价值跟踪，支持概览编辑与跟踪日志新增/编辑/删除。
- 所有新增、编辑、删除写入操作日志，支持按对象查看和全量检索。
- 负责人变更、状态变更、延期、价值跟踪等事件可触发通知（由通知中心场景配置决定是否实际发送）。

## **1.3 范围**

- 本期（当前生产已实现）：
    - 菜单入口：侧边栏「产品管理」，路由 `/quarterly-work`，支持 URL 参数 `year`、`quarter`（`quarter=all` 表示全年）。
    - 五个 Tab：产品目标、项目看板、任务看板、需求价值跟踪、操作日志。
    - 卡片 / 列表双视图（操作日志仅列表）。
    - 产品目标、项目、任务、价值跟踪的新增 / 编辑 / 删除（逻辑删除）。
    - 部门 Tab（仅系统管理员可见）、小组 Tab、年/季度筛选、名称模糊搜索。
    - 组织与权限中的「产品管理权限」三项能力。
    - 产品管理通知事件注册与定时扫描（延期、即将延期、价值跟踪待完成）。
- 不在本期页面主闭环内（代码中有模型或独立页，但产品管理主页面不作为主操作入口）：
    - `MonthlyWorkPlan` / `WeeklyWorkUpdate`（月度计划、周更新表仍存在，任务看板不提供周更新录入）。
    - 独立页面 `/value-tracking`（旧 ROI 页，价值跟踪主入口在本模块 Tab）。
    - 任务审批流（`QuarterlyWork.approvalStatus` 有字段，页面不展示、不流转）。

## **1.4 业务流程说明**

1. **规划产品目标。**有「管理产品目标」权限的用户在当年/指定年份下创建产品目标，指定负责人、描述、预期收益和状态。
2. **拆解项目。**有「管理项目与需求价值跟踪」权限的用户创建项目，必须至少关联一个产品目标，填写规划周期（起始季度 ~ 结束季度）。
3. **拆解任务。**有「管理任务」权限的用户在项目下创建任务，填写任务周期（起始月份 ~ 结束月份）、任务目标和负责人。任务卡片按结束月份计算「还剩 X.X 周 / 超期 X.X 周」。
4. **执行与状态更新。**任务在未启动 / 进行中 / 已完成 / 关闭之间手工切换。任务改为「进行中」时，若所属项目尚未上线，系统将项目同步为「进行中」。项目改为「已上线」或「已完成」时，必须已填写工作量（人天）。
5. **延期自动归列。**未完成且已超过计划结束时间的任务/项目，进入当前筛选季度下的「延期」列；已完成但实际完成时间超期的，按完成时间（或上线时间）所属季度进入延期列。
6. **上线后跟踪价值。**项目状态变为「已上线」后，初始化跟踪状态为「未观测」，进入需求价值跟踪。用户可编辑价值汇总，或新增跟踪日志（写一条日志并覆盖项目上的价值字段）。
7. **关闭或完成项目。**项目变为「已完成」或「关闭」时，同步将其下所有未删除任务改为相同状态，且不再作为价值跟踪可选项目。
8. **追溯。**上述新增、编辑、删除均写入操作日志。卡片上的日志图标、列表「日志」按钮、操作日志 Tab 均可查看。

## **1.5 对象关系与状态机**

层级关系：

```text
产品目标 ProductGoal  1 ── N  项目 Project（多对多，中间表 ProjectProductGoal）
项目 Project          1 ── N  任务 QuarterlyWork
项目 Project          1 ── N  价值跟踪日志 RequirementValueTrack
```

归属规则：

- 产品目标 / 项目 / 任务的组织归属取 **负责人所在组织节点** `orgNodeId`。
- 部门 Tab、小组 Tab 按该归属过滤；负责人必须属于当前部门范围内的在职用户。
- 删除均为逻辑删除（写 `deletedAt`），查询默认排除已删除数据。
- 删除项目时：级联逻辑删除其下任务和价值跟踪日志。
- 删除产品目标时：删除与项目的关联（`ProjectProductGoal`），**不删除**项目本身。

### 产品目标状态

| 状态码 | 展示名 | 看板列 | 说明 |
|--------|--------|--------|------|
| NOT_STARTED | 未启动 | 未启动 | 默认值 |
| IN_PROGRESS | 进行中 | 进行中 | 手工维护 |
| COMPLETED | 已完成 | 已完成 | 写入 `completedAt` |
| CLOSED | 关闭 | 关闭 | 写入 `completedAt` 为空（完成时间按状态为已完成才写） |
| LAUNCHED | 已上线 | 不单独成列 | 表单可选，但看板四列不包含「已上线」 |

产品目标看板 **没有延期列**，年/季度筛选 **不改变** 产品目标列表（只按部门/小组过滤）。

### 项目状态

| 状态码 | 展示名 | 看板列 | 说明 |
|--------|--------|--------|------|
| NOT_STARTED | 未启动 | 未启动 | 默认值；未超期且规划周期命中当前年/季 |
| IN_PROGRESS | 进行中 | 进行中 | 未超期且规划周期命中当前年/季 |
| LAUNCHED | 已上线 | 已上线 | 按 **上线时间** `launchedAt` 的年/季过滤；超期的不上本列 |
| COMPLETED | 已完成 | 无独立列 | 未超期的已完成项目 **不出现在四列看板**；超期的进入延期列 |
| CLOSED | 关闭 | 无独立列 | 未超期的关闭项目不出现在四列看板；超期的进入延期列 |
| （计算列） | 延期 | 延期 | 见 2.3.3，不是独立落库状态 |

项目延期判定：

- 计划结束日 = 结束季度（无则用起始季度）的季度最后一天。
- 未完成（非已完成/已上线）：当前时间晚于计划结束日 → 超期。
- 已上线：`launchedAt` 晚于计划结束日 → 超期。
- 已完成：`completedAt` 晚于计划结束日 → 超期。

### 任务状态

| 状态码 | 展示名 | 看板列 | 可否在表单手选 |
|--------|--------|--------|----------------|
| NOT_STARTED | 未启动 | 未启动（且未超期） | 是 |
| IN_PROGRESS | 进行中 | 进行中（且未超期） | 是 |
| COMPLETED | 已完成 | 已完成（且未超期） | 是 |
| CLOSED | 关闭 | 不单独成列；超期时进延期列 | 是 |
| DELAYED_COMPLETED | 延期 | 仅当超期时进入延期列 | **否**（表单不提供该选项；延期列是计算列） |

任务超期判定：以任务 `year` + `endMonth` 得到该月最后一天，与今天比较。

- 未到结束日：展示「还剩 X.X 周」（保留 1 位小数）。
- 已过结束日：展示「超期 X.X 周」，文案红色。

### 价值跟踪状态与价值判断

跟踪状态（存项目 `valueTrackStatus`）：

| 枚举 | 说明 |
|------|------|
| 未观测 | 项目刚上线时的初始值 |
| 观测中 | 已开始跟踪 |
| 已完成 | 价值跟踪结束 |

价值判断（存项目 `valueJudgement`）：

| 枚举 | 说明 |
|------|------|
| 未达预期 | |
| 已达预期 | |
| 超出预期 | |

规则：跟踪状态为「未观测」时，价值判断必须为空；不为「未观测」时，价值判断必填。

## **1.6 权限与数据范围**

位置：组织与权限 → 产品管理权限

三项能力：

| 能力键 | 名称 | 说明 | 控制的页面动作 |
|--------|------|------|----------------|
| MANAGE_PRODUCT_GOAL | 管理产品目标 | 允许创建、编辑与删除产品目标 | 新增/编辑/删除产品目标；卡片「+ 添加」 |
| MANAGE_PROJECT_AND_VALUE_TRACKING | 管理项目与需求价值跟踪 | 允许维护项目、项目价值判定及需求价值跟踪记录 | 新增/编辑/删除项目；新增/编辑/删除价值跟踪；编辑项目价值 |
| MANAGE_PRODUCT_TASK | 管理任务 | 允许创建、编辑与删除季度任务及任务看板内容 | 新增/编辑/删除任务 |

默认授权（可被组织页覆盖）：

| 角色 | 默认范围 |
|------|----------|
| 系统管理员 ADMIN | ALL |
| 部门主管 DEPARTMENT_MANAGER | SUBTREE（本部门及下级） |
| 组长 TEAM_LEADER | NODE（本组） |
| 普通成员 MEMBER | SELF |

**查看范围与写权限分离：**

- **查看**：非管理员按「用户所在部门整棵子树」加载产品目标/项目/任务/价值跟踪；管理员加载全部。部门内数据对部门成员公开可见。
- **写操作**：必须具备对应能力，否则按钮不展示；服务端无权限时返回明确错误，例如「当前角色不能管理任务」。
- **负责人可选范围**：当前部门及其下级组织内、`isActive=true` 且未删除的用户；支持搜索姓名。
- 无任何可选用户时（`canCreate=false`），四个「新增」按钮整组隐藏。

系统管理员可见顶部 **部门 Tab**；非管理员不显示部门 Tab，只显示本部门下的小组 Tab（含「全部」）。

## **2.2 产品目标**

### **2.2.1 流程概述**

- 产品目标按 **年** 规划，一张卡片/一行对应一条 `ProductGoal`。
- 看板四列：未启动、进行中、已完成、关闭。列头显示数量；有权限时列头提供「+ 添加」。
- 卡片展示：标题、负责人、小组名、年份。
- 卡片操作：查看操作日志、为该目标新增项目（预填产品目标）、编辑、删除。
- 列表操作：日志、编辑、删除。

### **2.2.2 卡片与列表字段**

卡片：

| 展示项 | 来源 |
|--------|------|
| 标题 | title |
| 负责人 · 小组 · 年份 | owner、teamName、year |

列表列：产品目标名称、负责人、年份、产品目标描述、预期收益、产品目标状态、创建时间、完成时间、操作。

时间展示精确到分钟，空为「—」。

### **2.2.3 新增 / 编辑表单**

弹窗标题：新增产品目标 / 编辑产品目标

| 字段 | 必选 | 类型及范围 | 说明 | 校验 |
|------|------|------------|------|------|
| 产品目标名称 | 是 | 字符串 | 输入 | 空则「产品目标名称为必填项」 |
| 负责人 | 是 | 部门内用户 | 可搜索选择器 | 空则「负责人为必填项」；不在部门范围则「负责人不在当前部门范围内」 |
| 年份 | 是 | 当年、当年+1、当年+2 | 下拉；默认当前筛选年 | 必须 4 位数字，否则「年份格式不正确」 |
| 产品目标描述 | 是 | 多行文本 | | 空则「产品目标描述为必填项」 |
| 预期收益 | 是 | 多行文本 | | 空则「预期收益为必填项」 |
| 产品目标状态 | 是 | 未启动/进行中/已上线/已完成/关闭 | 新增默认未启动 | 非法值「项目状态不正确」 |

按钮：取消、创建 / 保存。

状态变为已完成时写入 `completedAt`；改回非完成则清空完成时间。

### **2.2.4 删除**

- 二次确认：「确定删除这个产品目标吗？」并展示目标名称。
- 逻辑删除；同时删除与项目的关联，项目本身保留。
- 无权限：「产品目标不存在或无权限删除」。

### **2.2.5 操作日志备注**

| 动作 | 备注 |
|------|------|
| 新增 | 新增产品目标「{名称}」 |
| 编辑 | 按字段拼接：产品目标名称/年份/负责人/产品目标描述/预期收益/产品目标状态 从『旧』改为『新』；无变化不写 |
| 删除 | 删除产品目标「{名称}」 |

## **2.3 项目看板**

### **2.3.1 流程概述**

- 一个项目必须至少关联一个产品目标，可多选。
- 规划周期为 `YYYY-Q1` ~ `YYYY-Q4` 格式，起始不能晚于结束。
- 卡片四列：**未启动、进行中、延期、已上线**（没有「已完成」列）。
- 卡片展示：标题、负责人、小组、规划周期。
- 卡片操作：日志、为该项目新增任务（预填所属项目）、编辑、删除。
- 从产品目标卡片「+」进入新增项目时，预勾该产品目标。

### **2.3.2 卡片与列表字段**

列表列：项目名称、所属产品目标、负责人、规划周期、预期收益、工作量(人天)、项目状态、创建时间、上线/完成时间、操作。

所属产品目标：多个目标标题用顿号「、」拼接，无则「—」。

规划周期展示：`2026-Q1 ~ 2026-Q3`；仅有起始则「2026-Q1 起」。

上线/完成时间：优先 `launchedAt`，否则 `completedAt`。

### **2.3.3 年/季度与延期列规则**

| 列 | 入列条件 |
|----|----------|
| 未启动 | 状态=未启动，且未超期，且规划周期覆盖当前年（全年）或当前季 |
| 进行中 | 状态=进行中，且未超期，且规划周期覆盖当前年或当前季 |
| 已上线 | 状态=已上线，且未超期，且上线时间落在当前年（全年）或当前季 |
| 延期 | 见下 |

延期列（单季度）：

- 已上线或已完成且超期：上线时间（无则完成时间）的季度 = 当前筛选季度，且年份匹配。
- 其他超期（未启动/进行中/关闭）：**仅当筛选季度 = 今天所在季度** 时展示（未完成超期项目始终挂在「当前自然季」的延期列）。

延期列（全年）：

- 已上线：上线年份 = 筛选年。
- 已完成：完成年份 = 筛选年。
- 其他超期：规划周期与该年有交集。

无规划周期的项目：视为覆盖任意年/季（`projectRangeHasQuarter` / `projectRangeOverlapsYear` 在起止为空时返回 true）。

**验收注意：**按期完成或按期关闭的项目不会出现在四列看板上。

### **2.3.4 新增表单**

弹窗标题：新增项目

| 字段 | 必选 | 类型及范围 | 说明 | 校验 |
|------|------|------------|------|------|
| 项目名称 | 是 | 字符串 | | 「项目名称为必填项」 |
| 产品目标 | 是 | 多选当前可见产品目标 | 至少 1 个 | 「产品目标为必填项，请至少选择一个」；越权「产品目标不存在或无权限选择」 |
| 负责人 | 是 | 部门内用户 | | 同产品目标 |
| 规划周期 | 是 | 当年及下一年的 Q1–Q4 | 起始 ~ 结束 | 「起始季度为必填项」「结束季度为必填项」；格式须 `^\d{4}-Q[1-4]$`；起始晚于结束「起始季度不能晚于结束季度」 |
| 项目描述 | 是 | 多行 | 新增必填 | 「项目描述为必填项」 |
| 预期收益 | 是 | 多行 | 新增必填 | 「预期收益为必填项」 |
| 工作量(人天) | 条件必填 | 数字，步长 0.1，≥0 | 状态为已上线或已完成时必填 | 「项目状态为已上线或已完成时，工作量(人天)为必填项」；非数字「工作量格式不正确」；保存时四舍五入到 1 位小数 |
| 其他成本 | 否 | 多行 | | |
| 项目状态 | 是 | 未启动/进行中/已上线/已完成/关闭 | 默认未启动；从列头添加时带入该列状态 | |

新建为已上线：立即写 `launchedAt`，跟踪状态初始化为「未观测」，价值判断清空，并触发「项目已上线」通知。

新建为已完成：写 `completedAt`，触发「项目已完成」通知。

新建成功：触发「项目负责人变更」（首次指派）通知，写操作日志「新增项目「{名称}」」。

无产品目标可选时，多选器显示「暂无可选产品目标」。

### **2.3.5 编辑表单**

与新增字段基本相同，差异：

| 差异项 | 说明 |
|--------|------|
| 项目描述、预期收益、规划周期 | 编辑时服务端允许为空（可清掉） |
| 工作量 | 展示「任务工作量合计：X」，便于对照任务人天之和；已上线/已完成仍必填 |
| 页脚提示 | 「项目变更为已完成或关闭时，将同步更新其下所有任务状态，且不再有价值跟踪等后续事项。」 |
| 报错位置 | 弹窗内红字，不整页抛错，已填内容保留 |

状态副作用：

| 新状态 | 副作用 |
|--------|--------|
| 已上线（首次） | 保留或写入 `launchedAt`；跟踪状态=未观测，价值判断清空；校验已有工作量；发「项目已上线」 |
| 已完成 / 关闭 | 保留已有 `launchedAt`；已完成写 `completedAt`；其下所有未删除任务状态同步为已完成/关闭 |
| 退回未启动 / 进行中 | 清空 `launchedAt` |

更换负责人：发「项目负责人变更」通知。

### **2.3.6 删除**

- 确认文案：「确定删除这个项目吗？」
- 同时逻辑删除该项目下全部任务和价值跟踪日志。
- 无权限：「项目不存在或无权限删除」。

### **2.3.7 仅改状态（服务端能力）**

存在 `updateProjectStatus`：无独立页面入口时，仍作为后端规则。项目改为已上线前若工作量为空，报「项目变更为已上线前，请先编辑项目填写工作量(人天)」。

## **2.4 任务看板**

### **2.4.1 流程概述**

- 任务必须挂在项目下。可选项目排除已完成、已关闭项目。
- 任务周期为起始月份 ~ 结束月份（1–12 月），不直接选季度；季度由起始月计算：`floor((startMonth-1)/3)+1`。
- 任务年份：新建时取 **当天所在年**（不是筛选年）。
- 看板四列：未启动、进行中、延期、已完成。
- 卡片展示：任务标题、关联项目名称、负责人、任务结果（若有）、还剩/超期周数（超期红色）。
- 若存在月度计划数据，卡片可显示完成进度条；有延期完成的月度计划时显示「延期 N 周」（该进度来自 `MonthlyWorkPlan`，主流程不再录入月度计划）。
- 卡片操作：日志、编辑、删除。列头「+ 添加」按该列状态打开新增（延期列按未启动打开）。
- 从项目卡片「+」进入新增任务时，预填所属项目。

### **2.4.2 卡片与列表字段**

列表列：任务名称、所属项目、负责人、任务周期、剩余/超期、任务目标、工作量(人天)、任务状态、任务结果、创建时间、完成时间、操作。

任务周期展示：`3月~6月`。

列表中任务状态列使用任务 **落库状态** 的中文名（关闭显示「关闭」），与看板列「延期」不是同一概念。

### **2.4.3 年/季度过滤与延期列**

只保留 `year = 筛选年` 的任务（全年视图不过滤季度）。

单季度视图：

| 情况 | 是否出现在该季 |
|------|----------------|
| 已完成且超期 | 完成时间所在季度 = 筛选季（无完成时间则回退到任务季度） |
| 未完成且超期 | **始终出现**（挂在当前自然季延期，不要求任务原计划季等于筛选季） |
| 其他 | 任务季度（由 startMonth，否则 endMonth，再否则 year/quarter 字段）= 筛选季 |

列分配：

| 列 | 条件 |
|----|------|
| 未启动 | 状态=未启动 且未超期 |
| 进行中 | 状态=进行中 且未超期 |
| 已完成 | 状态=已完成 且未超期 |
| 延期 | 已超期，且状态为未启动/进行中/已完成/关闭/延期完成 |

### **2.4.4 新增 / 编辑表单**

弹窗标题：新增任务 / 编辑任务

| 字段 | 必选 | 类型及范围 | 说明 | 校验 |
|------|------|------------|------|------|
| 所属项目 | 是（界面） | 未完成且未关闭的项目 | 可搜索；展示只读「项目预期收益」 | 已完成/已关闭项目不可再挂新任务：「已完成或已关闭的项目不能新增季度工作」。未选项目且预期收益为空时，服务端「项目预期收益为必填项」 |
| 项目预期收益 | 只读 | 来自所选项目 | 随项目切换带出 | 服务端仍当必填字符串校验 |
| 任务名称 | 是 | 字符串 | | 「工作标题为必填项」（服务端字段名） |
| 负责人 | 是 | 部门内用户 | 默认优先任务原负责人、再项目负责人 | 同前 |
| 任务周期 | 否（界面有默认） | 1–12 月 | 新增默认当前月 ~ 当前月 | 起始晚于结束「起始月份不能晚于结束月份」；非法「月份格式不正确」。未传时新增用当前月，编辑用原值 |
| 任务描述 | 否 | 多行 | | |
| 任务目标 | 是 | 多行 | 对应库字段 description | 「本季度工作目标为必填项」 |
| 工作量(人天) | 状态=已完成时必填 | 数字 0.1 | | 「任务状态为已完成时，工作量(人天)为必填项」 |
| 任务状态 | 是 | 未启动/进行中/已完成/关闭 | 无「延期」选项 | 非法「状态不正确」；编辑时原状态若不允许手改「当前状态不允许手动变更」（`DELAYED_COMPLETED` 不可手改） |
| 任务结果 | 已完成时必填 | 未达标 / 已达标 / 超预期 | | 「任务结果为必填项」 |
| 任务执行概况 | 已完成时必填 | 多行 | | 「任务状态为已完成时，任务执行概况为必填项」 |

按钮：取消、创建 / 保存。

新建成功：发「季度任务负责人变更」，写「新增任务「{名称}」」。

编辑：

- 任务改为进行中：所属项目若非已上线，同步为进行中，并清空项目上线/完成时间。
- 更换项目时，新旧两个项目都可能被同步状态。
- 更换负责人：再发指派通知。
- 变更状态：发「季度任务状态变更」。
- 已完成：写 `completedAt`；改回非完成则清空。
- 无实际字段变化：不写操作日志。

### **2.4.5 删除**

- 确认：「确定删除这个任务吗？」
- 只逻辑删除该任务，不删除项目。
- 无权限：「任务不存在或无权限删除」。

## **2.5 需求价值跟踪**

### **2.5.1 流程概述**

- 仅 **已上线** 项目进入本 Tab。
- 列表模式上下两块：
    - 上方：需求价值概览（**一项目一行**）
    - 下方：价值跟踪日志（**一日志一行**，同一项目可多条）
- 卡片模式：按跟踪状态/价值判断分四列，**一项目一卡**，不展示日志明细。
- 顶部「+ 新增价值跟踪」、概览「新增跟踪」、卡片「+」打开同一新增日志弹窗。
- 概览「编辑」只改项目价值汇总，**不写新日志**。
- 新增跟踪会覆盖项目上的工作量/其他成本/实际收益/跟踪状态/价值判断，并以最后一次写入为准。

### **2.5.2 卡片列规则**

| 列 | 入列条件 |
|----|----------|
| 未观测 | 跟踪状态=未观测 |
| 观测中 | 跟踪状态=观测中，且价值判断不是「未达预期」 |
| 未达预期 | 价值判断=未达预期，且跟踪状态不是已完成 |
| 已完成 | 跟踪状态=已完成 |

卡片内容：项目名称、负责人、上线时间；操作：新增跟踪、编辑价值、删除项目（有权限时）。

### **2.5.3 概览列表**

列：项目名称、负责人、工作量(人天)、其他成本、预期收益、实际收益、跟踪状态、价值判断、项目状态、上线时间、操作。

操作：编辑、新增跟踪、查看日志（滚动并搜索到下方日志区）。

数据范围：权限内、状态=已上线、上线时间落在当前年/季（规则与项目看板「已上线」列一致，超期已上线不进概览）。

### **2.5.4 价值跟踪日志列表**

列：项目、负责人、跟踪时间、跟踪结果、后续优化、操作（编辑、删除）。

跟踪时间按 `trackedAt`，精确到秒。年/季按跟踪时间过滤。

### **2.5.5 新增价值跟踪**

弹窗标题：新增价值跟踪

可选项目：当前所有已上线项目（不限于当前季筛选后的概览，下拉为 `launchedProjectOptions`）。

| 字段 | 必选 | 说明 | 校验 |
|------|------|------|------|
| 项目 | 是 | 可搜索 | 非已上线：「项目不存在、未上线或无权限选择」 |
| 项目上线时间 | 只读 | | |
| 预期收益 | 只读 | | |
| 工作量(人天) | 只读展示，提交时带回 | 表单展示项目原值 | 可空；服务端按可选数字解析 |
| 其他成本 | 只读展示，提交时带回 | | |
| 实际收益 | 否 | 提示「本次修改会覆盖上次保存的内容」 | |
| 跟踪结果描述 | 是 | | 「跟踪结果描述为必填项」 |
| 跟踪状态 | 是 | 未观测/观测中/已完成；打开时默认观测中（若项目已是已完成则保持已完成） | 「价值跟踪状态不正确」 |
| 价值判断 | 跟踪状态≠未观测时必填 | 未达预期/已达预期/超出预期 | 「价值判断为必填项」 |
| 后续优化 | 否 | | |

提交：更新项目价值字段 + 插入一条日志 + 发「价值判断变更」（若判断或状态变化）+ 项目操作日志「新增价值跟踪记录：…字段变更」。

### **2.5.6 编辑项目价值（概览编辑）**

只读：项目名称、负责人、上线时间、预期收益。

可改：工作量(人天)*、其他成本、实际收益、跟踪状态*、价值判断（条件必填）。

工作量必填：「工作量(人天)为必填项」。不写日志。项目必须仍为已上线。

### **2.5.7 编辑 / 删除跟踪日志**

编辑：可改实际收益、跟踪状态、价值判断、跟踪结果描述*、后续优化；同步写回项目价值字段。

删除：逻辑删除该条日志，**不回滚**项目上的价值汇总；项目日志备注「删除价值跟踪记录」。二次确认。

## **2.6 操作日志**

### **2.6.1 全量 Tab**

- 位置：产品管理 → 操作日志
- 无卡片模式，固定表格。
- 最多加载 1000 条，按时间倒序。
- 列：时间、对象类型、对象名称、操作人、操作内容、操作备注。
- 对象类型：产品目标 / 项目 / 任务。
- 操作内容：新增 / 编辑 / 删除。
- 按部门/小组过滤（取对象当前归属）；年/季不过滤。
- 搜索对象名称、操作内容、备注、操作人。

### **2.6.2 对象级日志弹窗**

- 入口：各对象卡片日志图标、列表「日志」。
- 标题：`操作日志：{对象名称}`
- 列：操作人、操作内容、时间、操作备注。
- 无数据：「暂无操作日志」。

价值跟踪的新增/编辑/删除记在 **项目** 对象上，不单独作为「价值跟踪」对象类型。

## **2.7 通知与延期预警**

通知是否真正发出，取决于通知中心是否启用对应场景。以下为产品管理已注册、代码会 emit 的事件，改版后行为应保持一致。

### **2.7.1 即时事件**

| 事件码 | 名称 | 触发时机 |
|--------|------|----------|
| quarterly_work.assigned | 季度任务负责人变更 | 新建任务；或编辑时更换负责人 |
| quarterly_work.status.changed | 季度任务状态变更 | 编辑任务且状态变化 |
| project.assigned | 项目负责人变更 | 新建项目；或编辑时更换负责人 |
| project.launched | 项目已上线 | 新建即为已上线，或首次改为已上线 |
| project.completed | 项目已完成 | 新建即为已完成，或首次改为已完成 |
| project.value_judgement.changed | 价值判断变更 | 新增/编辑跟踪或编辑项目价值，且判断或跟踪状态变化 |

跳转模板一般为 `/quarterly-work?year={{year}}&quarter={{quarter}}`（部分事件无年季参数）。

### **2.7.2 定时扫描**

扫描未删除、仍处于未启动/进行中的任务（有结束月）和项目（有规划结束季度）。

| 事件码 | 名称 | 规则 |
|--------|------|------|
| quarterly_work.overdue | 季度任务延期 | 今天已过任务结束月最后一天 |
| quarterly_work.due_soon | 季度任务即将延期 | 距结束日的天数落入场景配置阈值 |
| project.overdue | 项目延期 | 今天已过规划结束季度最后一天 |
| project.due_soon | 项目即将延期 | 距季度结束日天数落入阈值 |
| project.value_track.pending | 价值跟踪待完成 | 已上线且跟踪状态仍为未观测，距本季度结束日天数落入阈值 |

另：注册表中 `todo.due_soon` 归在产品管理模块，但本模块业务 **不写 TodoItem**，主流程不依赖该事件。

## **2.8 组织与权限配置**

- 位置：组织与权限 → 产品管理权限 Tab
- 系统范围可批量同步到各部门；部门范围维护本部门角色默认权限。
- 未保存变更时提示「有未保存的产品管理权限调整」。
- 保存后产品管理页按钮显隐立即按新授权生效（需刷新/重新进入）。
- 说明文案：控制产品目标、项目与需求价值跟踪、任务看板的维护权限。

# **三、验收与测试依据**

改版后功能测试以本章为通过标准。交互样式可改，**业务规则、字段必填、状态副作用、过滤口径、权限边界** 必须等价，除非改版需求明确废止某条。

## **3.1 页面与筛选**

- [ ] 侧边栏「产品管理」进入 `/quarterly-work`，标题与副标题文案在。
- [ ] 默认 Tab 为任务看板，默认卡片视图。
- [ ] 管理员可见部门 Tab；非管理员不可见部门 Tab。
- [ ] 小组 Tab 含「全部」及当前部门小组；切部门后小组回到全部。
- [ ] 年默认当前年，季度默认当前季，可切「全部」。
- [ ] 切换年/季后 URL 带 `year`、`quarter`，刷新不丢。
- [ ] 产品目标列表不随年/季变化；项目/任务/价值跟踪随年/季变化。
- [ ] 搜索为包含匹配、不区分大小写；清空后恢复。
- [ ] 卡片/列表切换不丢失当前 Tab 与筛选。

## **3.2 权限**

- [ ] 无「管理产品目标」：无新增/编辑/删除产品目标，只读可见范围内数据。
- [ ] 无「管理项目与需求价值跟踪」：无项目与价值跟踪写操作。
- [ ] 无「管理任务」：无任务写操作。
- [ ] 负责人不能选外部门用户。
- [ ] 越权提交服务端拒绝，并给出对应中文错误。

## **3.3 产品目标**

- [ ] 必填项为空无法提交，错误文案与 2.2.3 一致。
- [ ] 创建后出现在对应状态列，卡片显示负责人、小组、年份。
- [ ] 从目标卡片可预填该目标新增项目。
- [ ] 删除需二次确认；删除后目标消失，原关联项目仍在，所属产品目标变为「—」或其余目标。
- [ ] 编辑有变更才写日志。

## **3.4 项目**

- [ ] 必须至少选一个产品目标；多选保存后列表顿号拼接。
- [ ] 起始季度晚于结束季度：提示「起始季度不能晚于结束季度」。
- [ ] 状态改为已上线/已完成但工作量为空：拦截。
- [ ] 首次改为已上线：进入已上线列（按上线时间所在季），跟踪状态=未观测。
- [ ] 改为已完成/关闭：其下任务全部同步该状态。
- [ ] 按期完成的项目不出现在四列看板。
- [ ] 未完成超期项目出现在 **当前自然季度** 的延期列。
- [ ] 删除项目后任务和跟踪日志一并不可见。
- [ ] 编辑失败时弹窗内报错，内容不丢失。

## **3.5 任务**

- [ ] 不能往已完成/已关闭项目下新建任务。
- [ ] 已完成必须填工作量、任务结果、执行概况。
- [ ] 任务结果仅「未达标 / 已达标 / 超预期」。
- [ ] 超期文案红色「超期X.X周」，未超期「还剩X.X周」。
- [ ] 未完成超期任务出现在任务看板延期列；已完成且按期的在已完成列。
- [ ] 任务改为进行中时，项目从末上线状态变为进行中。
- [ ] 表单不能手选「延期」。
- [ ] 新建任务的年份为当天年份。

## **3.6 价值跟踪**

- [ ] 未上线项目不能新增跟踪。
- [ ] 概览一项目一行；同一项目多条日志只增加日志表行，不复制概览行。
- [ ] 卡片按 2.5.2 四列归类；未达预期且未完成跟踪归「未达预期」列。
- [ ] 新增跟踪覆盖项目价值字段；概览编辑不新增日志。
- [ ] 跟踪状态=未观测时不要求价值判断；其他状态必填价值判断。
- [ ] 删除日志不回滚项目汇总字段。
- [ ] 列表模式下方有「价值跟踪日志」标题。

## **3.7 操作日志与通知**

- [ ] 新增/编辑/删除三类对象均能在对象弹窗和操作日志 Tab 查到。
- [ ] 编辑无字段变化不产生新日志。
- [ ] 价值跟踪相关日志的对象类型为「项目」。
- [ ] 更换任务/项目负责人、任务状态变化、项目上线/完成会发出对应事件（在通知场景启用时，通知中心能收到）。
- [ ] 任务/项目过期后，定时扫描可产生延期类通知（场景启用时）。

## **3.8 已知现状（改版时需显式决定保留或废止）**

以下不是缺陷清单，而是当前实现特性，验收时不要按「理想设计」误判，除非新产品方案已改：

1. 产品目标不受年/季度筛选。
2. 项目看板没有「已完成」「关闭」列；按期完成/关闭的项目在看板上消失。
3. 任务「延期」是计算列，不是可选手动状态。
4. 主页面不提供周更新录入，尽管库表仍在。
5. 任务审批状态字段存在但不在 UI 使用。
6. 独立 `/value-tracking` 页不是本模块主入口。
7. 卡片操作是日志 / 编辑 / 删除（及上下文「新增下级」），**没有复制**。
8. 操作日志全量最多 1000 条。
9. 新增任务的 `year` 用今天的年份，即使用户正在浏览其他年。
10. 未完成的超期任务/项目，在「非当前自然季」的单季视图里，任务仍会出现在延期列，项目仅在当前自然季的延期列出现。
