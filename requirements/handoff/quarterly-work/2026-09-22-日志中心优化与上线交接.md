### 1. 修复 Hydration 错误 ✅

**问题根因**：
- `AuditFilters` 组件在 `useEffect` 中从 `window.location.search` 读取 URL 参数
- 服务端渲染时使用空值，客户端挂载后更新状态
- 导致 React hydration 不匹配错误

**解决方案**：
```typescript
// 服务端页面 (page.tsx)
export default async function LogsPage({ searchParams }: Props) {
  const params = await searchParams;
  const initialFilters = {
    startDate: params.startDate,
    endDate: params.endDate,
    // ...
  };
  
  return <AuditFilters initialFilters={initialFilters} />;
}

// 客户端组件 (audit-filters.tsx)
export function AuditFilters({ initialFilters }: Props) {
  const [filters, setFilters] = useState(initialFilters);
  // 不再使用 useEffect 读取 URL
}
```

**相关文件**：
- `src/app/(authenticated)/logs/page.tsx`
- `src/app/(authenticated)/logs/audit-filters.tsx`
- `src/app/(authenticated)/logs/content.tsx`

## 🔍 技术要点

### 1. Next.js 14 App Router SSR 规范

**核心原则**：服务端和客户端渲染的内容必须一致

**正确做法**：
```typescript
// ✅ 服务端传递数据给客户端
export default async function Page({ searchParams }) {
  const params = await searchParams;
  return <ClientComponent initialData={params} />;
}
```

**错误做法**：
```typescript
// ❌ 客户端组件在 useEffect 中读取 URL
function ClientComponent() {
  useEffect(() => {
    const params = new URLSearchParams(window.location.search);
    setFilters(params); // 导致 hydration 不匹配
  }, []);
}
```

### 2. Prisma 关系查询优化

**使用 `include` 减少查询次数**：
```typescript
// ✅ 一次查询获取关联数据
const logs = await prisma.personalKpiActionLog.findMany({
  include: {
    personalKpi: {
      include: { user: true }
    }
  }
});

// ❌ N+1 查询问题
const logs = await prisma.personalKpiActionLog.findMany();
for (const log of logs) {
  const kpi = await prisma.personalKpi.findUnique({
    where: { id: log.personalKpiId },
    include: { user: true }
  });
}
```

### 3. 适配器模式

**统一接口，不同实现**：
- 每种日志表有自己的适配器
- 统一映射为 `UnifiedAuditRecord`
- 各自定制 `objectName` 的构造逻辑
