# 价值跟踪与首版完成度 — 现网数据迁移方案

> 对应实施交接：`requirements/handoff/quarterly-work/2026-10-13-价值跟踪与首版完成度实施交接.md`
> 执行方：生产环境会话（depot-clean 职责边界：本地合入 main 后，由生产会话执行本文）。执行预计 30 分钟内，低峰期操作。

---

## 0. 前置检查

- [ ] 生产机已装 pnpm 并能正常 `pnpm install`（若首次用 pnpm，先完成 pnpm 迁移验证）;
- [ ] 代码已合入 main 并部署到生产机（应用先不发，先发数据库）;
- [ ] 确认当前无人正在填报价值跟踪（低峰期）。

## 1. 备份（必须）

```bash
cp <生产数据库文件> <生产数据库文件>.bak-20261013-before-value-tracking
```

验证备份可打开：`sqlite3 <备份文件> "SELECT COUNT(*) FROM Project;"`

## 2. 结构迁移（含内置数据迁移）

```bash
pnpm prisma migrate deploy --config db/prisma.config.ts
pnpm prisma generate --config db/prisma.config.ts
```

按时间戳顺序执行 5 个迁移，其中 3 个带数据迁移 SQL:

| 迁移 | 结构变更 | 内置数据迁移 |
|---|---|---|
| `20261012100000_extend_requirement_value_track` | RequirementValueTrack 重建（trackingResult 可空 + 13 个新字段） | `未观测 → 待观测` |
| `20261013100000_add_project_first_version_workload` | Project +首版/迭代工作量快照字段 | — |
| `20261013110000_project_workload_snapshot` | Project +总工作量快照 | — |
| `20261013120000_add_value_track_judgement_snapshot` | RequirementValueTrack +valueJudgement/actualValue | 历史记录用项目当前值回填 |
| `20261013130000_add_project_needs_development` | Project +needsDevelopment | 已上线 或 存在开发需求 → 是 |

迁移后冒烟（预期无报错、有返回值）:

```sql
SELECT COUNT(*) FROM Project WHERE needsDevelopment = 1;
SELECT COUNT(*) FROM Project WHERE valueTrackStatus = '待观测';
SELECT COUNT(*) FROM Project WHERE valueTrackStatus = '未观测';   -- 必须为 0
```

## 3. 重启应用

```bash
pnpm install   # 如依赖有变化
# 重启 next 服务（prisma client 变更必须重启）
```

此时系统已可用：新项目走新逻辑，历史项目尚未回填（下一步处理）。

## 4. 历史数据回填

### 4.1 预检（不写库）

```bash
pnpm tsx scripts/backfill-value-track-periods.ts
```

输出四类结果，逐一确认：

- **冲突清单**（同项目同周期多条记录）：脚本跳过不处理，导出给业务确认合并/保留；
- **已完成但无上线时间**的项目：不纳入统计，确认是否符合预期；
- 有跟踪记录但无上线时间、填报时间早于上线时间的记录：人工确认；
- 待回填条数、待补齐任务数、待重算快照项目数。

### 4.2 执行回填

```bash
pnpm tsx scripts/backfill-value-track-periods.ts --apply
```

执行内容：历史记录回填周期字段与 completedAt → 开发项目补齐两条跟踪任务（幂等）→ 全量项目重算首版完成度快照。

## 5. 验证清单

- [ ] 价值跟踪列表只出现：开发项目 / 有上线时间的项目；从未上线的终态项目不出现；
- [ ] 已上线项目各有两条跟踪任务（第 1、2 次跟踪，带周期区间与截止日期）;
- [ ] 项目卡片首版完成度显示百分比或「-」（抽查 2~3 个有需求工作量的项目手工核算）;
- [ ] 新建开发需求 → 项目快照自动更新；删除最后一个开发需求 → 项目退出价值跟踪列表；
- [ ] 新建项目选「是否开发项目=否」→ 状态下拉无「已上线」;
- [ ] 操作日志中有上线、填报、工作量变更记录。

## 6. 回滚方案

- **回填前发现结构问题**：应用回滚到上一版本 + `cp` 恢复备份数据库；
- **回填后发现数据问题**：回填脚本只新增/更新周期字段与快照字段，不删数据；可用备份对照修复，或按项目重跑 `recalcProjectWorkloadSnapshot`；
- 「未观测→待观测」在迁移里已执行，回滚应用代码前需评估旧代码对「待观测」的兼容性（旧代码不认识该值——回滚必须先恢复数据库备份）。
