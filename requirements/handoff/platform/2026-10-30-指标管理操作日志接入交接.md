**关联现象**：指标管理列表「最后更新」有 10/30 记录，日志中心 `/logs` 仅有发布、通知等系统类记录，无业务修改

## 一、结论（给产品/运维）

| 能力 | 现状 |
|------|------|
| 指标谁改过、何时改过（列表列） | 有：`updatedById` / `progressUpdatedAt` 等业务字段 |
| 日志中心统一审计 | **无**：`src/server/annual-goals/actions.ts` 未调用 `writeOperationLog` / `writeAuditEvent` |
| 日志中心「业务操作」Tab | UI 已包含模块 **年度指标**（`ANNUAL_GOAL`），查询层假定数据在 **OperationLog**（见 `audit-query-service.ts` 142–146 行） |
| 钉钉登录 | 回调 `src/app/login/dingtalk/callback/route.ts` **不写** `AUTH` 审计（密码登录在 `auth/actions.ts` 会写）— 与「今天有人登录但日志里没有」可能有关，**本需求范围外、可作 follow-up** |

**根因**：不是日志中心故障，是指标管理写路径从未接入 OperationLog；列表「最后更新」≠ 日志中心。

## 二、推荐方案（与现有产品管理一致）

### 2.1 写入通道

- **采用 `OperationLog`**（复用 `src/server/quarterly-work/operation-log.ts` 的 `writeOperationLog`），**不要**为指标再 duplicate 一套到 `AuditEvent`（除非后续要做跨模块统一 before/after JSON）。
- **事务**：凡已在 `prisma.$transaction` 内的写操作，在同一 `tx` 内 `writeOperationLog(tx, …)`；单次 `create/update` 无事务的，改为 `$transaction` 包裹「业务写 + 日志」，符合建设方案「日志失败则业务回滚」。

### 2.2 `targetType` 扩展（字符串，无 Prisma 枚举）

在 `src/server/quarterly-work/operation-log-constants.ts` 增加常量（命名与现有 `PRODUCT_GOAL` / `PROJECT` / `QUARTERLY_WORK` 一致，**全大写下划线**）：

| 常量建议 | 中文标签（日志展示） | 典型 `targetId` | 典型 `targetTitle` |
|----------|----------------------|-----------------|-------------------|
| `ANNUAL_GOAL_PLAN` | 年度方案 | `plan.id` | `plan.name`（如「移动商城 2026 年度方案」） |
| `ANNUAL_GOAL_METRIC` | 部门指标 | `metric.id` | `metric.name` 或 `metricCode + name` |
| `ANNUAL_GOAL_METRIC_SOURCE` | 元指标 | `source.id` | `source.name` |
| `ANNUAL_GOAL_METRIC_ASSIGNMENT` | 小组承接 | `assignment.id` | 承接指标名 + 小组名（remark 里写清） |
| `ANNUAL_GOAL_QUARTER` | 季度指标/进度 | `quarterTarget.id` 或 `metricId` | 指标名 + `2026 Q3` 等 |

`action` 继续用现有：`OPERATION_LOG_ACTION_CREATE` / `_UPDATE` / `_DELETE`（值分别为「新增」「编辑」「删除」）。

`remark`：优先用 `buildFieldChangeRemark`（`operation-log.ts`）生成「字段从 A 改为 B」；批量周进度可一条汇总，例如：`更新 2026 Q4 周进度：指标 A 本周 +10；指标 B 本周 +5`。

### 2.3 日志中心适配器（**必做，否则模块筛不准**）

文件：`src/server/audit/adapters/operation-log-adapter.ts`

1. **`mapTargetTypeToModule`**：为上述 `ANNUAL_GOAL_*` 映射到 `AUDIT_MODULES.ANNUAL_GOAL`（当前未知 type 会落到 `PRODUCT_MANAGEMENT`，会导致「年度指标」筛选仍看到产品日志或看不到指标日志）。
2. **`getTypePrefix` / `formatActionName` / `objectTypeNames`**：补中文类型与操作文案。
3. **查询过滤（建议一并修）**：`queryAuditLogs` 合并多源后，若 `options.modules` 非空，应对结果 **`filter(record => modules.includes(record.module))`**；否则仅选「年度指标」时仍会拉出全部 OperationLog 且 module 映射错误。  
   可选增强：`buildOperationLogWhere` 增加 `targetTypes?: string[]`，在 `determineDataSources` 仅查 `ANNUAL_GOAL` 时传入各 `ANNUAL_GOAL_*`。

### 2.4 代码组织（二选一）

- **A（推荐）**：新建 `src/server/annual-goals/operation-log.ts`，封装 `writeAnnualGoalOperationLog` + 各实体 remark 构建，actions 里只调 helper。  
- **B**：直接在 `actions.ts` 内调用 `writeOperationLog`（改动面大、易漏）。

## 三、需接入的 Server Actions 清单

文件：`src/server/annual-goals/actions.ts`

| 函数 | 操作 | 日志要点 |
|------|------|----------|
| `createAnnualGoalPlan` | 新增 | plan；remark：年份、部门 |
| `updateAnnualGoalPlan` | 编辑 | 对比 year/description/部门等 |
| `deleteAnnualGoalPlan` | 删除 | 软删方案 |
| `createAnnualGoalMetric` | 新增 | 含小组承接/部门指标等多分支，按实际创建实体写 type |
| `updateAnnualGoalMetric` | 编辑 | **高频**（含 `assignmentId` 小组权重分支）；对比 name/target/weight/risk 等 |
| `deleteAnnualGoalMetric` | 删除 | |
| `createAnnualGoalMetricSource` | 新增 | 元指标 |
| `updateAnnualGoalMetricSource` | 编辑 | |
| `deleteAnnualGoalMetricSource` | 删除 | |
| `saveAnnualGoalQuarterTargets` | 编辑 | 季度目标批量；可按 quarter 变化写 remark 或一条汇总 |
| `updateAnnualGoalQuarterProgress` | 编辑 | **用户截图场景（改季度进度）**；current/target 变化 |
| `updateAnnualGoalWeeklyProgress` | 编辑 | 批量周增量；一条或按行 |
| `deleteAnnualGoalQuarterTargets` | 删除 | 清空季度指标 |

**不记录**（建设方案第六节）：纯查询、筛选、未提交表单、**无字段变化的重复保存**（对比前后值，无 diff 则 skip `writeOperationLog`）。

**已有通知**：`emitAnnualGoalTargetChanged` / `emitAnnualGoalRiskChanged` 等是**通知链路**，不能替代 OperationLog；日志与通知可同时存在。

## 五、自测清单

### 5.1 功能

1. 管理员或有指标编辑权限账号登录。  
2. 指标管理 → 选 2026 季度指标 → 修改某指标 **当前值/进度** 并保存。  
3. 打开 **日志中心** `/logs`：  
   - Tab **业务操作**（或「全部」+ 模块 **年度指标**）；  
   - 应出现：**操作人 = 当前用户**（非「系统」）、模块 **年度指标**、操作 **编辑…**、业务对象含指标名称、备注含字段变化。  
4. 再测：新建/编辑部门指标、元指标、小组承接权重、保存季度目标、周进度批量更新、删除（若有权限）。  
5. **无变化保存**：不应新增一条 OperationLog。

### 5.2 数据

```bash
# 开发库示例（路径按本地 DATABASE_URL）
sqlite3 db/dev.db "SELECT datetime(createdAt/1000,'unixepoch','localtime'), targetType, action, targetTitle, substr(remark,1,80) FROM OperationLog WHERE targetType LIKE 'ANNUAL_GOAL%' ORDER BY createdAt DESC LIMIT 10;"
```

（若 Prisma 存 ISO 字符串，改用 Node 小脚本或 Prisma Studio 查 `OperationLog`。）

### 5.3 回归

- 产品管理改项目/需求：日志仍正常，module 仍为 **产品管理**。  
- 模块筛选 **年度指标** 时：不应再混入产品管理 OperationLog（依赖第三节适配器 + 后过滤）。
