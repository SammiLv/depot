# 菜单切换慢 — 性能问题记录

**日期**：2026-08-24  
**环境**：生产 `http://depot.rj-info.com`（`C:\appdeploy\depot`，SQLite `db/dev.db`）  
**现象**：同事线上与本机访问均反馈点击左侧菜单很久才有反应；KPI 页可打开但数据加载慢。

---

## 结论摘要

服务**未挂**（80 端口正常、HTTP 200）。慢在**登录后服务端渲染（SSR）**，不是网络或进程退出。

| 根因 | 影响 |
|------|------|
| 人才/KPI 页首屏一次拉过多数据 | 单页 3–10 秒 |
| Node 进程内存膨胀（~4GB） | 全局 GC 卡顿，所有菜单都慢 |
| 部署后未强刷（Server Action 哈希变化） | 部分操作失败/重试 |
| 历史 `.next` chunk 缺失（lucide-react） | 个别页（如年度指标）曾报错；当前年度指标已正常 |

---

## 代码层原因（供后续优化）

### 1. 人才发展页 `/talent`

`src/app/(authenticated)/talent/page.tsx` 首屏并行加载：

- 盘点配置/周期/详情、业务考核、工作事故、决策、履历、员工档案、职业/胜任力/决策规则配置等
- 对每个可见员工调用 `getProfileOverviewExtras`（`profile-overview-query.ts`），**每人多次 DB 往返**
- admin 全量可见时 participant 集合大，耗时与 payload 体积陡增

### 2. KPI 页 `/kpi`

`src/app/(authenticated)/kpi/page.tsx` 同时调用：

- `getKpiData`
- `getBusinessAssessmentPageData`
- `getWorkIncidentPageData`  
并对 assessment/incident 做 `JSON.parse(JSON.stringify(...))` 深拷贝。

### 3. Authenticated Layout

`src/app/(authenticated)/layout.tsx` 每次导航执行用户、组织节点、菜单权限查询（相对较轻，~7ms 量级）。

### 4. 通知调度器

`src/server/notifications/scheduler.ts` 生产环境每 60s tick，与 SSR 共用单 Node 进程；高负载时可能加剧排队（非主因，但需注意）。

## 中长期优化建议（需改代码，未实施）

1. **人才页按需加载**：总览/盘点/档案等 tab 进入再 fetch，首屏不拉全量。
2. **`getProfileOverviewExtras` 批量化**：合并为单次或少量 SQL，消除 N+1。
3. **KPI 页拆分**：业务考核、工作事故改为 tab 懒加载；去掉不必要的深拷贝。
4. **RSC payload 瘦身**：人才页 485KB 响应体过大，考虑分页/字段裁剪。
5. **监控**：重启后观察 Node RSS；若再次涨到 3GB+ 需查内存泄漏或缓存策略。
6. **部署流程**：pull 后必须 build + restart；通知用户关闭旧标签页。
