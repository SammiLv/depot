# 产品管理列表模式切 Tab 仍显示任务数据

**日期**：2026-08-31  
**环境**：生产 `http://depot.rj-info.com/quarterly-work`（只查、未改代码）  
**模块**：产品管理（`/quarterly-work`）→ 列表模式  
**现象**：列表模式下，从「任务看板」切到「项目看板」或「产品目标」，表头变成对应列名，但第一列及行数据仍是任务。卡片模式不明显。

---

## 结论摘要

不是库里把任务写成了产品目标/项目，也不是服务端三类数据拼错。列表三个 Tab 的表格 DOM 结构几乎一样，外层是**无 `key` 的 Fragment**。从任务切走时 React **复用**了任务列表的表格节点：表头文案按位置更新，行节点没按新 Tab 拆掉，仍渲染任务 `title`。

页面默认 Tab 就是「任务看板」（`board`），所以一进页 → 切列表 → 再切目标/项目，几乎必现。

| 项 | 说明 |
|----|------|
| 根因 | 列表表格无 `key={tab}`，切 Tab 时复用任务列表 DOM |
| 不是 | 产品目标/项目表里真有同名记录；查询接口把 `columns` 赋给了目标/项目 |
| 为何卡片正常 | 看板列 `key` 不同（`not_started` vs `goal_not_started` vs `project_not_started`），会整列重挂 |
| 代码改动 | **无**（本次只记录） |

---

## 复现路径

1. 打开产品管理（默认就是「任务看板」）。
2. 右上角切到「列表」。
3. 点「产品目标」或「项目看板」。
4. 标题、搜索框占位、表头会变，但行仍是任务名称。

## 代码依据

### 1. 默认 Tab 是任务看板

`src/app/(authenticated)/quarterly-work/content.tsx`：

```ts
const [tab, setTab] = useState<BoardTab>("board");
const [viewMode, setViewMode] = useState<ViewMode>("card");
```

### 2. 三个 Tab 都是无 key 的 Fragment + 结构几乎相同的表格

```tsx
{tab === "goal" ? (
  <>
    <BoardSearchBar title="产品目标" ... />
    {viewMode === "card" ? (/* 卡片 */) : (/* 列表表格 */)}
  </>
) : tab === "project" ? (
  <>
    <BoardSearchBar title="项目看板" ... />
    {viewMode === "card" ? (/* 卡片 */) : (/* 列表表格 */)}
  </>
) : tab === "board" ? (
  <>
    <BoardSearchBar title="任务看板" ... />
    {viewMode === "card" ? (/* 卡片 */) : (/* 列表表格 */)}
  </>
) : ...}
```

列表根节点都是 `div.overflow-* + 表头 grid + divide-y 行`，没有 `key={tab}`。React 按类型复用：

- `BoardSearchBar`：同一组件，title/placeholder 更新 → 标题看起来对了。
- 表头格子：无 key、按位置更新文案 → 列名变成「产品目标名称 / 项目名称」。
- 行：`key={item.id}`，切 Tab 后未按新数据集拆干净 → 第一列仍是任务名。

源码里列表数据源本身是分开的，**不是写错变量**：

- 产品目标：`filteredProductGoalColumns.flatMap(...)`
- 项目：`filteredProjectColumns.flatMap(...)`
- 任务：`filteredTaskColumns.flatMap(...)`

服务端 `getQuarterlyWorkData` 也是三套列：`productGoalColumns` / `projectColumns` / `columns`，分别来自 `ProductGoal` / `Project` / `QuarterlyWork`。

### 3. 卡片模式为何正常

卡片按列渲染，列 key 不同，切 Tab 会卸载旧列、挂新列，所以卡片里能看到正确的产品目标/项目。

## 不改代码时的确认 / 临时绕过

1. **卡片 → 产品目标**：应出现上面 4 条能力建设。
2. **保持卡片，再切列表**：列表新挂载，应仍是这 4 条。
3. **任务看板 + 列表 → 再点产品目标**：又变回任务那三条。

临时给业务看数：先切「卡片」，再切目标/项目，最后才切「列表」。不要从任务列表直接点目标/项目。

刷新页面会回到默认「任务看板」，从列表再切走仍会复现。

---

## 修复方向（尚未实施）

1. **给列表（以及整个 Tab 内容根）加 `key={tab}` 或 `key={`${tab}-${viewMode}`}`**，切 Tab 时整表卸载重建。这是最小修复。
2. 三个 Tab 抽成独立列表组件，避免 Fragment 对位复用。
3. 列表 `flatMap` 行 key 建议用 `${column.key}-${item.id}`：任务看板里超期未启动会同时出现在「未启动」和「延期」，扁平化后会重复 `item.id`，加重 reconciler 错乱。本次截图三条任务在 8/31 尚未超期，不是主因，但是隐患。

本次按生产排查要求，**未改任何代码**。
