# 年度指标生产迁移 — 命令清单（copy-paste 版）

**生产地址**：http://depot.rj-info.com/（80 端口）  
**编排入口**：`scripts/annual-goals-migration/run.sh`  
**前置条件**：本地改造已 push 到 main，生产机可 `git pull`

## Windows 生产机说明（必读）

生产目录示例：`C:\appdeploy\depot`

| 终端 | 能否跑迁移 | 说明 |
|------|-----------|------|
| **Git Bash** | ✅ | 推荐，与 `depot-prod.sh` 一致 |
| **CMD / PowerShell** | ❌ 不能直接跑 `.sh` | 仅适合 `git pull`、`npm install`；跑脚本见下方「从 CMD 调用 Git Bash」 |

**Git Bash 路径写法**：`C:\appdeploy\depot` → `/c/appdeploy/depot`

```bash
# 打开 Git Bash 后
cd /c/appdeploy/depot
git pull
bash scripts/annual-goals-migration/run.sh status
```

**CMD 里仅检查文件是否存在**（不是跑脚本）：

```cmd
cd C:\appdeploy\depot
dir scripts\annual-goals-migration\run.sh
```

**从 CMD 调用 Git Bash 跑脚本**（未打开 Git Bash 窗口时）：

```cmd
cd C:\appdeploy\depot
"C:\Program Files\Git\bin\bash.exe" scripts/annual-goals-migration/run.sh status
```

Git 若装在其他盘，把路径改成实际的 `bash.exe` 位置。

## 阶段 A：发布前（本地 Mac）

```bash
# 1. 确认改造已提交并推送（在本地 depot-clean 目录）
git status
git push origin main
```

## 阶段 B：预迁移（T-3～7 天，生产机不停服）

在生产服务器 **Git Bash** 中（不是 CMD），进入项目目录后逐条执行：

```bash
cd /c/appdeploy/depot   # 按实际路径修改

# 1. 拉最新代码
git pull

# 2. 按需安装依赖
npm install --registry=https://registry.npmmirror.com

# 3. 查看迁移状态
bash scripts/annual-goals-migration/run.sh status

# 4. 预迁移：Phase1 加法迁移 + dry-run（旧应用继续运行）
bash scripts/annual-goals-migration/run.sh pre-migrate
# 提示时输入 yes
```

### 审查 dry-run 报告

报告目录：`requirements/handoff/prod-env/`

| 文件 | 关注点 |
|------|--------|
| `*-承接回填-dry-run-报告.csv` | `severity=ERROR` 必须为 0 |
| `*-季度归一-dry-run-报告.csv` | 冲突行需业务确认保留值 |

若生产出现本地没有的冲突，需更新 `scripts/annual-goals-migration/data/phase3-migrate-quarter-targets.ts` 中 `confirmedConflictDecisions` 后重新 push，再在生产机 `git pull` 并重跑：

```bash
bash scripts/annual-goals-migration/run.sh dry-run
```

## 阶段 C：正式切换（T-0 维护窗口，约 30～60 分钟）

**开始前**：通知业务方年度指标模块停写。

```bash
# 1. 拉最新代码（若预迁移后又 push 过）
git pull
npm install --registry=https://registry.npmmirror.com

# 2. 再次确认状态
bash scripts/annual-goals-migration/run.sh status

# 3. 一键正式切换（停服 → 备份 → 数据 apply → 迁移 2/3 → build → 启服）
bash scripts/annual-goals-migration/run.sh cutover
# 提示时输入 yes
```

### 可选：分步手动（与 cutover 等价）

```bash
bash scripts/depot-prod.sh stop
cp db/dev.db "db/dev.db.bak-$(date +%Y%m%d-%H%M%S)-manual"

bash scripts/annual-goals-migration/run.sh restore-hold   # 若 Phase2/3 仍在暂存区则跳过
bash scripts/annual-goals-migration/run.sh cutover --skip-backup   # 已手动备份时用
bash scripts/annual-goals-migration/run.sh cutover --skip-start    # 迁移完成但不启服
bash scripts/depot-prod.sh start
```

## 回滚（切换失败时）

```bash
ls -lt db/dev.db.bak-*

bash scripts/annual-goals-migration/run.sh rollback --backup=db/dev.db.bak-YYYYMMDD-HHMMSS-before-annual-goal-cutover
# 提示时输入 yes

git log --oneline -10
git checkout <迁移前commit> -- .
npm install
npm run prisma:generate
npm run build
bash scripts/depot-prod.sh start
```

## 常见问题

| 现象 | 处理 |
|------|------|
| `migrate deploy` 唯一索引失败 | 不要继续 Phase 3；用 rollback 恢复备份，检查 dry-run CSV |
| `npm: command not found` | Git Bash 需先加 Node 到 PATH，见下方「npm 找不到」 |
| Phase2/3 被误移走 | `bash scripts/annual-goals-migration/run.sh restore-hold` |
| cutover 后 build 失败 | 服务已停；修复代码后 `npm run build && bash scripts/depot-prod.sh start` |

### npm 找不到（Git Bash）

Git Bash 默认 PATH 不含 Node。先探测 node 位置：

```bash
# 在 Git Bash 中逐个试，哪个有输出就用哪个
"/c/Program Files/nodejs/node.exe" -v
"/c/Users/rj/.workbuddy/binaries/node/versions/22.22.2/node.exe" -v
```

手动加 PATH 后再跑迁移（路径按上面实际结果改）：

```bash
export PATH="/c/Windows/System32:/c/Users/rj/.workbuddy/binaries/node/versions/22.22.2:$PATH"
node -v && npm -v
bash scripts/annual-goals-migration/run.sh pre-migrate
```

若 Phase2/3 已在上一轮被暂存，直接重跑 `pre-migrate` 即可（脚本会跳过已暂存项）。
