# 年度指标模型重构 — 全链路可执行计划

**日期**：2026-07-28  
**状态**：执行中（本地 Phase 0～6 已完成，待 Phase 7 生产迁移）
**目标**：取消小组方案和小组指标副本，建立“部门年度容器 → 部门指标 → 元指标 → 共享季度指标”，通过独立承接表支持多小组协作。

---

## 1. 业务规则基线

1. 年度方案只属于部门；不再创建小组年度方案。
2. 年度指标由部门自上而下制定，不走审批流程。
3. 部门年度指标可以拆成多个元指标。
4. 一个部门指标或元指标可以由一个或多个小组共同承接。
5. 小组承接只保存小组独有信息，不复制指标名称、目标值、单位等权威字段。
6. 同一部门指标或元指标只有一套 Q1～Q4，多承接小组共同查看和维护。
7. 部门也可直接维护季度拆解；这是权限差异，不产生另一套季度数据。
8. 季度当前值更新后，同步重算元指标及部门年度指标的 `currentValue`。
9. 多个小组承接同一指标时，共享季度值只汇总一次。
10. 删除沿用项目软删策略；有效数据唯一约束使用部分唯一索引。

### 典型场景

```text
产品部 2026 年度指标容器
└─ 创新 ToC：35000 人
   ├─ C端产品：30000 人
   │  ├─ 承接：C端组
   │  ├─ 承接：设计组
   │  └─ 共享季度：Q1 3000 / Q2 7500 / Q3 10500 / Q4 9000
   └─ 其他创新 ToC：5000 人
```

C端组与设计组读取、维护同一套“C端产品”季度目标和进度。

## 2. 目标数据模型

### 2.1 `AnnualGoalPlan`：精简部门年度容器

仅负责部门、年度和整体生命周期：

```prisma
enum AnnualGoalPlanStatus {
  DRAFT
  ACTIVE
  CLOSED
}

model AnnualGoalPlan {
  id                  String               @id @default(cuid())
  year                Int
  departmentOrgNodeId String
  name                String
  description         String?
  status              AnnualGoalPlanStatus @default(DRAFT)
  createdById         String
  createdAt           DateTime             @default(now())
  updatedAt           DateTime             @updatedAt
  deletedAt           DateTime?

  metrics AnnualGoalMetric[]

  @@index([departmentOrgNodeId, year])
  @@index([status])
  @@index([deletedAt])
}
```

删除字段：

- `ownerType`
- `ownerOrgNodeId`
- `parentPlanId`
- `version`
- `isActive`
- `approvalStatus`
- `effectiveFrom` / `effectiveTo`
- `approvedAt`
- `revisionReason`
- `revisedFromPlanId`

生命周期：

- `DRAFT`：部门维护指标、元指标、承接关系和季度拆解。
- `ACTIVE`：进入执行，可按权限调整定义并更新季度进度。
- `CLOSED`：只读。

同一部门同一年度只允许一个有效容器：

```sql
CREATE UNIQUE INDEX "AnnualGoalPlan_active_department_year_key"
ON "AnnualGoalPlan" ("departmentOrgNodeId", "year")
WHERE "deletedAt" IS NULL;
```

### 2.2 `AnnualGoalMetric`：只保存部门年度指标

保留部门指标权威字段：

- `planId`
- `metricCode`
- `name` / `description`
- `targetValue` / `currentValue` / `unit`
- `weight`
- `calculationType` / `riskStatus`
- `responsibleUserId` / `sortOrder`
- 审计与软删字段

删除：

- `sourceMetricId`
- 小组承接用途的反向关系

迁移完成后，本表不得再出现 TEAM 指标副本。

### 2.3 `AnnualGoalMetricSource`：元指标

继续通过 `parentMetricId` 指向部门年度指标，保存元指标权威字段。

规则：

- 元指标目标值合计不得超过父年度指标目标值。
- 若部门指标存在有效元指标，其 `currentValue` 由元指标 `currentValue` 汇总。
- `metricCode` 的唯一约束需兼容软删，改为有效行部分唯一索引。

### 2.4 新增 `AnnualGoalMetricAssignment`：小组承接关系

```prisma
model AnnualGoalMetricAssignment {
  id                String   @id @default(cuid())
  teamOrgNodeId     String
  metricId          String?
  sourceMetricId    String?
  weight            Float
  responsibleUserId String?
  sortOrder         Int      @default(0)
  createdById       String
  updatedById       String?
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
  deletedAt         DateTime?

  metric       AnnualGoalMetric?
  sourceMetric AnnualGoalMetricSource?

  @@index([teamOrgNodeId])
  @@index([metricId])
  @@index([sourceMetricId])
  @@index([responsibleUserId])
  @@index([deletedAt])
}
```

数据库约束：

```sql
-- metricId / sourceMetricId 必须且只能填写一个
CHECK (
  ("metricId" IS NOT NULL AND "sourceMetricId" IS NULL)
  OR
  ("metricId" IS NULL AND "sourceMetricId" IS NOT NULL)
);

CREATE UNIQUE INDEX "AnnualGoalAssignment_active_team_metric_key"
ON "AnnualGoalMetricAssignment" ("teamOrgNodeId", "metricId")
WHERE "deletedAt" IS NULL AND "metricId" IS NOT NULL;

CREATE UNIQUE INDEX "AnnualGoalAssignment_active_team_source_key"
ON "AnnualGoalMetricAssignment" ("teamOrgNodeId", "sourceMetricId")
WHERE "deletedAt" IS NULL AND "sourceMetricId" IS NOT NULL;
```

承接表不保存 `name/targetValue/unit/currentValue`，避免副本不同步。

### 2.5 `AnnualGoalQuarterTarget`：共享季度指标

季度指标直接指向权威部门指标或元指标：

```text
metricId 非空、sourceMetricId 为空：部门指标季度拆解
metricId 为空、sourceMetricId 非空：元指标季度拆解
```

建议把当前必填的 `metricId` 改为 nullable，并增加二选一 CHECK。

有效季度唯一索引：

```sql
CREATE UNIQUE INDEX "AnnualGoalQuarter_active_metric_key"
ON "AnnualGoalQuarterTarget" ("metricId", "year", "quarter")
WHERE "deletedAt" IS NULL AND "metricId" IS NOT NULL;

CREATE UNIQUE INDEX "AnnualGoalQuarter_active_source_key"
ON "AnnualGoalQuarterTarget" ("sourceMetricId", "year", "quarter")
WHERE "deletedAt" IS NULL AND "sourceMetricId" IS NOT NULL;
```

### 2.6 `AnnualGoalProgress`：共享季度进度

- `quarterTargetId` 指向共享季度指标。
- `updaterId` 记录实际更新人。
- 本阶段保留 `metricId/sourceMetricId` 以降低迁移风险，但统一改为权威指标引用。
- 后续可评估仅保留 `quarterTargetId`。
- 如需统计各协作小组贡献，后续新增 `contributorOrgNodeId`，不能复制季度指标。

### 2.7 `AnnualGoalRevisionLog`

当前代码未消费该表，且方案不再做版本修订。本次数据审计确认无必须保留记录后删除该表；如存在审计数据则导出归档后删除。

## 3. 权限与生命周期

### 3.1 部门权限

具备对应部门年度指标维护能力的用户可以：

- 创建和维护部门年度容器
- 维护年度指标、元指标和承接关系
- 维护共享季度指标和进度
- 切换 `DRAFT / ACTIVE / CLOSED`

### 3.2 小组权限

当前用户所在小组存在有效 `AnnualGoalMetricAssignment`，且角色具备相应能力时：

- 查看被承接的部门指标或元指标
- 查看所有协作小组共享的 Q1～Q4 和进度
- 维护共享季度拆解与进度

小组权限不再依赖 TEAM `AnnualGoalPlan`。

### 3.3 状态控制

- `DRAFT`：允许定义和执行准备。
- `ACTIVE`：允许进度更新；指标定义是否可调整沿用部门权限。
- `CLOSED`：所有指标、季度和进度只读。

不再调用通用审批流处理年度方案。

---

## 4. 当前值汇总规则

季度进度更新必须在同一事务内完成：

1. 更新 `AnnualGoalProgress`。
2. 重算对应共享 `AnnualGoalQuarterTarget.currentValue`。
3. 若季度目标属于元指标：
   - 汇总该元指标所有有效季度 `currentValue`
   - 更新 `AnnualGoalMetricSource.currentValue`
   - 汇总父指标所有有效元指标 `currentValue`
   - 更新 `AnnualGoalMetric.currentValue`
4. 若季度目标直接属于部门指标：
   - 汇总该指标所有有效季度 `currentValue`
   - 更新 `AnnualGoalMetric.currentValue`
5. `AnnualGoalMetricAssignment` 不参与数值求和。
6. 若直属部门指标没有任何有效季度行，迁移及普通查询不得将现有 `currentValue` 自动归零；首次创建或更新季度数据后再切换为季度汇总值。

同一元指标被 C端组和设计组共同承接时，只按共享季度行计算一次。

**本地测试库状态**：已完成正式 `--apply`。30 条有效季度行已归一为 26 组，4 条 TEAM 季度行已软删；Q1/Q2 保留已确认的部门权威值，Q3/Q4 合并一致数据。二次 dry-run 显示待规范、待软删和 currentValue 待更新均为 0。

规范键：

- 部门指标：`metricId + year + quarter`
- 元指标：`sourceMetricId + year + quarter`

合并规则：

1. 只有一条 TEAM 季度行：迁移为权威季度行。
2. 已有权威季度行且 TEAM 行完全一致：保留权威行。
3. 多个小组季度行完全一致：保留一条。
4. 目标值、当前值、日期或风险状态不一致：写 conflict CSV，不自动选择。
5. `AnnualGoalProgress.quarterTargetId` 重指向保留行。
6. `AnnualGoalProgress.metricId/sourceMetricId` 改成权威引用。
7. 被替代的季度行软删，不物理删除。

本地已确认的数据裁决：

- “C端产品”Q1 保留部门值 2187，舍弃小组值 2165。
- “C端产品”Q2 保留部门值 2619，舍弃小组值 2836。
- Q3/Q4 双方一致，保留部门规范行。
- “创新 ToB 营收”允许按元指标/季度数据重算为 0。
- 无季度拆解的直属指标保持原 `currentValue`。

冲突清零后才允许准备正式切换，但此时不单独在生产执行 `--apply`。

#### 权限

- 部门方案权限只按 `departmentOrgNodeId`。

- `CLOSED` 统一只读。

## 8. 风险与回滚

| 风险 | 处理 |
|---|---|
| TEAM 指标无法匹配部门权威指标 | dry-run 输出 unmatched CSV，人工确认后再 apply |
| 多合作小组历史季度值冲突 | 不自动覆盖，业务确认保留值 |
| 进度引用遗漏 | 合并事务重指向，验收无失效 quarterTargetId |
| 权限范围扩大或缩小 | 新旧查询双读对比，并增加合作小组权限测试 |
| currentValue 重复累计 | 只聚合权威季度行，Assignment 永不参与数值求和 |
| 清理过早导致回滚困难 | 加法迁移、应用切换、验收、清理迁移分开执行 |
| 生产回滚 | 恢复数据库备份并回退应用版本 |

- 本阶段不实现按协作小组拆分贡献值。

## 10. 完成标准

1. `AnnualGoalPlan` 仅作为精简的部门年度生命周期容器。
2. `AnnualGoalMetric` 只包含部门年度指标。
3. `AnnualGoalMetricSource` 保存元指标。
4. `AnnualGoalMetricAssignment` 完整表达单/多小组承接。
5. `AnnualGoalQuarterTarget` 保存权威共享季度指标。
6. 季度进度正确同步元指标和年度指标当前值。
7. 无小组方案、无指标展示副本、无多套季度数据。
8. 测试环境和生产迁移均有备份、dry-run、验收和回滚路径。
