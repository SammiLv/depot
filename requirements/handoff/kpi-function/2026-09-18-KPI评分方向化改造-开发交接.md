## 1. 背景与问题

2026-09-18 现网发生 KPI 提交自评问题，集中体现在**分值填写**：

1. 指标项该填正数还是负数**没有提示、前端没有限制**，用户体验差；
2. 指标项的计分方向（扣分制/加分制）当前是**按名称硬编码判断**的——前后端共 3 处 `item.name.includes("奖励")`：
   - `src/app/(authenticated)/kpi/[id]/content.tsx`（提交前校验，2 处）
   - `src/server/kpi/actions.ts` `parseKpiItemScore`（服务端校验，1 处）
   
   模板改名/改名不含"奖励"二字，这套判断就失效，定制代码要跟着改。
3. **隐形 bug（汇总口径）**：`calculatePenaltyTotal` / 详情页汇总用 `Math.min(score, 0)`，**正数被直接丢弃**——奖励项填了正分也不计入总分。

---

## 2. 改造目标

1. KPI 模板指标项增加「计分方向」字段：扣分项（填 ≤0）/ 加分项（填 ≥0），替代名称硬编码；
2. 评分详情页：方向提示 + 输入即时校验 + 公司标准 Toast 提醒；
3. 汇总口径修正：加分项正数计入总分；
4. 加分项**不设上限**（已确认，靠审核把关）。

---

## 3. 数据模型（schema + 迁移）

新增枚举 `KpiScoreDirection { DEDUCTION, BONUS }`：

- `KpiTemplateItem.scoreDirection` —— 模板项方向，默认 DEDUCTION
- `PersonalKpiItem.scoreDirection` —— 初始化 KPI 单据时从模板项**冻结拷贝**（`sourceTemplateItemId` 回链），模板后续修改不影响已生成单据（与现有模板冻结语义一致）

**纪律（血泪教训，见 9d1131f 漏迁移事故）**：schema 变更必须带迁移文件：
- 手写 `db/prisma/migrations/<timestamp>_add_kpi_score_direction/migration.sql`（ADD COLUMN，**不要**用 migrate diff 自动生成的整表重建，会丢数据）
- 本地验证用 `prisma migrate deploy --config db/prisma.config.ts`（先停服务防锁库）；开发环境已全面弃用 `db push`，与现网 migrate deploy 对齐
- `migrate diff --from-migrations --to-schema` 验证零差异后再提交

## 6. 评分详情页（`src/app/(authenticated)/kpi/[id]/content.tsx`）

1. **方向提示**：每个指标项输入框旁标注——扣分项「填 0 或负数」/ 加分项「填 0 或正数」（placeholder 或后缀）
2. **即时校验**：input/blur 时校验方向，错了立即 error toast（如「"指标完成奖励"为加分项，只能填写 0 或正数」）；提交前统一再校验一遍
3. **服务端兜底**：`parseKpiItemScore` 改为按单据冻结的 `scoreDirection` 校验，删除名称硬编码（前后端 3 处全清）

---

## 7. 汇总口径修正（`kpi-query.ts` 详情汇总 + `actions.ts` `calculatePenaltyTotal` 链路）

- 现状：`阶段总分 = Σ(满分) − Σ|负数|`（正数被丢弃）
- 改为：`阶段总分 = Σ(item.score + item.阶段分)`
  - 扣分项：满分 + 负值 = 扣分后得分 ✓
  - 加分项：分值（通常 0）+ 正值 = 加分后得分 ✓
- 影响面：自评/组长评/主管评/终审四层汇总、详情页展示、列表四列得分——统一走新口径
- 注意兼容：存量单据的奖励项若有正数，改后总分会变化（这是修正，需在验收时确认一条历史单据前后对比）
