# 人才能力评估规则配置化 & 业务考核/工作事故迁移进度交接

## 一、当前总览

本次交接涵盖**两个已基本验证通过的并行改造**：

1. **人才能力评估规则配置化**
   - 将原「人才盘点模型」入口升级为「人才能力评估」。
   - 新增「人才能力测算模型」子模块，支持配置 KPI 权重与人才盘点权重。
   - 人才画像中的「能力匹配度」计算改为读取 ACTIVE 规则版本的权重，默认兜底 `0.6 / 0.4`。

2. **业务考核 & 工作事故迁移至 KPI 管理**
   - 将「人才发展」页面下的「业务考核」「工作事故」操作工作台迁移到「KPI 管理」页面。
   - KPI 管理顶部 Tab 顺序为：季度 KPI → 业务考核 → 工作事故 → KPI 模板。
   - 新增 KPI 能力项 `MANAGE_BUSINESS_ASSESSMENT`、`MANAGE_WORK_INCIDENT`，默认授权给 ADMIN / 部门经理。
   - 数据可见性调整为「部门内公开」，同一部门下所有成员可见。

3. **补充优化（刚完成）**
   - KPI 管理页面的年份/季度筛选器适配到「业务考核」「工作事故」Tab。
   - 季度筛选增加「全部」选项（`quarter=0`），支持查看当年度全部数据。

## 二、人才能力评估规则配置化

### 2.1 数据模型

`db/prisma/schema.prisma` 的 `TalentReviewTemplateVersion` 表新增两个字段：

```prisma
kpiWeight    Float @default(0.6)
reviewWeight Float @default(0.4)
```

迁移文件已生成：

- `db/prisma/migrations/20260820090000_add_ability_weights_to_review_template/migration.sql`

```sql
ALTER TABLE "TalentReviewTemplateVersion" ADD COLUMN "kpiWeight" REAL NOT NULL DEFAULT 0.6;
ALTER TABLE "TalentReviewTemplateVersion" ADD COLUMN "reviewWeight" REAL NOT NULL DEFAULT 0.4;
```

> 生产环境执行时该迁移为**非破坏性**：新增字段带默认值，现有记录会自动填充 `0.6 / 0.4`，无需回刷历史数据。

### 2.2 规则配置入口

- 入口标题从「人才盘点模型」改为「人才能力评估」。
- 进入后拆分为两个子 Tab：
  - **人才能力测算模型**：配置 KPI 权重、人才盘点权重，两者之和必须为 1。
  - **人才盘点模型**：保留原有维度、评分档、等级区间、九宫格规则配置。

### 2.3 Server Action 调整

`src/server/talent/review-actions.ts`：

- 创建版本时默认写入 `kpiWeight: 0.6`、`reviewWeight: 0.4`。
- 新增/复用权重更新 Action，仅草稿版本可编辑权重。
- 发布时校验 `kpiWeight + reviewWeight === 1`，否则阻止发布。

### 2.4 计算逻辑改造

`src/server/talent/profile-overview-query.ts`：

- 查询用户所属部门的 `ACTIVE` `TalentReviewTemplateVersion`。
- 读取 `kpiWeight` / `reviewWeight` 替换硬编码 `0.6 / 0.4`。
- 无 ACTIVE 规则时默认兜底 `0.6 / 0.4`。

### 2.5 前端文案动态化

人才画像「能力匹配度」卡片的说明文案根据当前权重动态展示：

```
(当前聘期内 KPI 均值 / 季度 KPI 总分) × 60% + (当前聘期内盘点均值 / 盘点模型总分) × 40%
```

百分比随权重配置变化。

## 三、业务考核 & 工作事故迁移至 KPI 管理

### 3.1 页面结构

`src/app/(authenticated)/kpi/content.tsx` 的 `SectionTab` 扩展为：

```ts
type SectionTab = "quarterly-kpi" | "business-assessment" | "work-incident" | "kpi-template";
```

Tab 顺序：

1. 季度 KPI
2. 业务考核
3. 工作事故
4. KPI 模板

### 3.2 组件复用

从 `src/app/(authenticated)/talent/operation-workspaces.tsx` 导入：

- `BusinessAssessmentQuarterlyWorkspace`
- `WorkIncidentWorkspace`

迁移后由 `kpi/content.tsx` 根据当前 Tab 条件渲染，原有业务逻辑不变。

### 3.3 权限模型

`src/server/permissions/permission-constants.ts`：

- `kpiAbilityKeys` 新增：
  - `manageBusinessAssessment: "MANAGE_BUSINESS_ASSESSMENT"`
  - `manageWorkIncident: "MANAGE_WORK_INCIDENT"`
- `kpiOrdinaryPermissionAbilityKeys` 加入上述两项，使其在权限配置页面可配。
- `kpiDefaultPermissionGrants` 默认授权：
  - `ADMIN`：ALL 作用域，默认开启。
  - `DEPARTMENT_MANAGER`：SUBTREE 作用域，默认开启。
  - `TEAM_LEADER`、`MEMBER`：默认不授予维护权限。
- 清理 `talentDefaultPermissionGrants` 中已迁移的维护类权限。

`src/app/(authenticated)/organization/page.tsx` 的 `kpiPermissionPresentation` 补充中文名称：

- `MANAGE_BUSINESS_ASSESSMENT` → 维护业务考核
- `MANAGE_WORK_INCIDENT` → 维护工作事故

### 3.4 Server Action 权限检查迁移

`src/server/talent/assessment-actions.ts` 和 `src/server/talent/incident-actions.ts`：

- 所有 `requireAbility(talentAbilityKeys.manageBusinessAssessment)` 改为 `requireAbility(kpiAbilityKeys.manageBusinessAssessment)`。
- 工作事故同理。
- 数据查询范围保持按当前用户所在部门过滤。

### 3.5 人才发展页面清理

`src/app/(authenticated)/talent/content.tsx`：

- 顶部 Tab 移除「业务考核」「工作事故」。
- 移除对应组件导入与渲染。
- 页面描述更新。
- 规则配置中的「业务考核规则」「工作事故等级配置」卡片保留不动。

### 3.6 数据可见性

- 业务考核批次、工作事故记录按「当前用户所在部门」过滤。
- 同一部门内所有成员默认可见，不再通过 `VIEW_BUSINESS_ASSESSMENT` / `VIEW_WORK_INCIDENT` 做列表级隔离。
- 只保留 talent 模块中人才画像/决策等只读场景继续使用 `viewBusinessAssessment`、`viewWorkIncident`。

### 3.7 年月筛选适配（本次补充）

`src/app/(authenticated)/kpi/page.tsx`：

- 将 `selectedYear` / `selectedQuarter` 传给 `getBusinessAssessmentPageData` 和 `getWorkIncidentPageData`。

`src/server/talent/assessment-query.ts`：

- 接受 `options?: { selectedYear?: number; selectedQuarter?: number }`。
- `selectedQuarter === 0` 表示查看当年度全部季度。
- 按 `year + quarter` 过滤 cycles、rules、imports；关联数据通过 `cycleIds` 隐式过滤。

`src/server/talent/incident-query.ts`：

- 接受 `options?: { selectedYear?: number; selectedQuarter?: number }`。
- `selectedQuarter === 0` 表示查看当年度全部季度。
- 按 `occurredAt` 的年/季度过滤 `incidents`；关联数据通过 `incidentIds` 隐式过滤。

`src/app/(authenticated)/kpi/content.tsx`：

- 年份/季度筛选器从「季度 KPI」Tab 移出，三个操作 Tab 均显示。
- 季度下拉增加「全部」选项（`value=0`）。
- 筛选器使用 `selectedYear` / `selectedQuarter` 保持 URL 与 UI 一致。
- 「当前看板」文案针对季度 KPI / 业务考核 / 工作事故分别显示。

## 六、已知问题与后续建议

1. **生产环境迁移**
   - 数据库迁移 `20260820090000_add_ability_weights_to_review_template` 为新增非空字段带默认值，执行时通常不会丢数据，但建议上线前在备份库上先演练一次。
   - 旧 `talentAbilityKeys.manageBusinessAssessment` / `manageWorkIncident` 的权限矩阵记录在生产环境中可能仍残留。建议上线后执行一次权限矩阵同步脚本，或让管理员在「组织与权限 → KPI 管理权限」中重新确认授权。

2. ** talent 模块残留引用**
   - 已确认 `viewBusinessAssessment`、`viewWorkIncident` 仍保留在 talent 能力项中，供人才画像/决策只读场景使用。
   - 若后续需要完全下线 talent 中的查看能力项，需同步调整人才画像和人才决策的查询逻辑。

3. **规则配置保留位置**
   - 「业务考核规则」「工作事故等级配置」仍保留在「人才发展 → 规则配置」中，未迁移到 KPI 管理。若后续要统一入口，需第二轮改造。

4. **工作事故与 KPI 扣分联动**
   - 迁移后 server action 调用路径不变，仅调整权限 key。KPI 扣分联动逻辑未受影响，但建议回归验证一次。

5. **筛选器「全部」季度**
   - 当前实现：URL 中 `quarter=0` 表示全部，后端按整年过滤；季度 KPI Tab 在 `quarter=0` 时会回退到当前季度（保持原逻辑），不影响使用。

```bash
npm run dev:kpi
```

当前 dev server 端口为 `3004`。

### 关键验证路径

1. **人才能力评估**
   - 人才发展 → 规则配置 → 人才能力评估 → 新建/编辑版本 → 调整权重 → 发布。
