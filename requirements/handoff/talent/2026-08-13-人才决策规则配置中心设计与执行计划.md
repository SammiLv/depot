# 人才决策规则配置设计与执行计划

日期：2026-08-13  
文档状态：设计已确认，按轮执行  
制度基准：以正式制度为准

## 一、建设目标

建设“人才决策规则配置”，用于定义并发布以下规则信息：

> 当某一业务来源的字段满足指定条件时，未来的人才决策引擎应生成哪些员工限制或处理记录。

配置中心只保存规则定义，不读取具体员工进行匹配，不执行规则，不生成员工限制记录，也不作出人才决策。

示例：

```text
规则名称：A级事故

触发条件：
工作事故.事故等级 = A

规则输出：
- KPI扣分110分，作用于当季度
- 奖励限制1年
- 调薪限制1年
- 晋升限制1年
- 取消当年度年终奖
```

## 二、系统职责边界

### 2.1 本阶段建设范围

- 员工档案缺失字段补齐；
- 人才决策规则列表；
- 人才发展主工作台内职责分离的新建、编辑和查看视图；
- 触发字段目录；
- 单字段触发条件配置；
- 多项规则输出配置；
- 草稿、发布、停用和修订历史；
- 发布前完整性和冲突校验；
- 规则内容预览；
- 权限和审计日志；
- 正式制度规则初始化。

### 2.2 本阶段明确不建设

- 员工档案派生事实的自动聚合；
- 人才盘点、晋升或聘期事件监听；
- 人才决策引擎；
- 员工数据扫描和规则匹配；
- 员工限制记录生成、到期或解除；
- 人才决策建议；
- 人才决策结果。

配置中心不得出现“执行规则”“匹配员工”“生成限制”等入口。

## 三、与现有业务模块的关系

工作事故、KPI、业务考核、人才盘点和员工档案是独立业务模块。人才决策规则配置只引用这些模块提供的字段，不取代其业务规则。

```text
工作事故规则 ────── 提供事故等级
KPI等级规则 ─────── 提供KPI等级
业务考核规则 ────── 提供考核等级或是否合格
人才盘点模型 ────── 提供盘点等级
员工档案 ───────── 提供聘期派生事实
                         ↓
                人才决策规则配置
                         ↓ 发布规则定义
              未来的人才决策引擎
```

必须保留：

- `WorkIncidentRuleVersion`及工作事故规则配置；
- `KpiRatingRuleVersion`、`KpiRatingBand`及KPI等级配置；
- 业务考核规则；
- 人才盘点模型；
- 员工档案。

以上模块不属于旧人才决策配置清理范围。

## 四、员工档案字段设计

### 4.1 已有并继续使用的字段

- 姓名；
- 入职日期；
- 人才岗位；
- 当前职级；
- 入职薪资；
- 当前薪资；
- 档案备注。

### 4.2 新增基础与聘期字段

| 字段 | 类型 | 当前维护方式 | 用途 |
|---|---|---|---|
| 入职职级 | 职级关联 | 人工维护 | 保留入职时的职级起点 |
| 当前聘期开始日期 | 日期 | 人工维护 | 当前聘期边界 |
| 当前聘期结束日期 | 日期 | 人工维护 | 当前聘期边界及续聘节点 |
| 当前聘期期数 | 正整数 | 人工维护 | 第1期、第2期等 |

### 4.3 新增人才决策事实字段

| 字段 | 类型 | 配置中心读取方式 |
|---|---|---|
| 聘期内人才盘点2次C | 三态布尔 | 员工档案.该字段 = 是/否 |
| 聘期内人才盘点连续2次C | 三态布尔 | 员工档案.该字段 = 是/否 |
| 续聘前最近一次人才盘点为C级 | 三态布尔 | 员工档案.该字段 = 是/否 |
| 当前聘期内是否有正式晋升 | 三态布尔 | 员工档案.该字段 = 是/否 |

三态定义：

- `null`：待更新；
- `true`：是；
- `false`：否。

“待更新”不得被解释为“否”。同时保存人才决策事实最后更新时间和更新说明。

上述四项由其他业务事件在未来负责聚合并更新员工档案。配置中心和人才决策引擎只读取最终档案值，不配置和执行次数、连续次数、聘期范围等聚合过程。

## 五、规则配置模型

每一条正式制度规则独立配置，基本结构为：

```text
规则基本信息
  + 一个触发条件
  + 一个或多个规则输出
```

### 5.1 规则基本信息

| 字段 | 必填 | 说明 |
|---|---:|---|
| 规则名称 | 是 | 例如A级事故、KPI为C级 |
| 规则类别 | 是 | 工作事故、KPI、业务考核、人才盘点、员工档案 |
| 适用部门 | 是 | 使用组织名称选择，不输入内部ID |
| 制度依据 | 否 | 正式制度名称和版本 |
| 规则说明 | 否 | 业务解释 |
| 生效日期 | 是 | 规则开始适用日期 |
| 失效日期 | 否 | 长期有效可为空 |
| 优先级 | 是 | 供未来冲突处理使用 |
| 修订说明 | 否 | 本次调整原因 |

系统自动生成内部编码和修订序号，不要求用户输入内部标识。

### 5.2 触发条件

本阶段一条规则只支持一个触发字段：

```text
数据来源 → 触发字段名称 → 运算符 → 触发字段值
```

示例：

```text
工作事故 → 事故等级 → 等于 → A
员工档案 → 聘期内人才盘点2次C → 等于 → 是
```

本阶段不提供：

- 多条件组合；
- 统计范围；
- 次数聚合；
- 连续次数；
- 公式编辑；
- 自定义脚本。

### 5.3 字段目录

字段目录由系统注册并控制，用户只能选择业务名称。

每个字段定义包含：

- 字段显示名称；
- 数据来源；
- 数据类型；
- 枚举选项；
- 可用运算符；
- 业务说明；
- 数据责任模块；
- 是否启用。

第一批字段：

| 数据来源 | 字段 | 类型 | 可选值 |
|---|---|---|---|
| 工作事故 | 事故等级 | 枚举 | S、A、B、C、D |
| 季度KPI结果 | KPI等级 | 枚举 | S、A、B、C、D |
| 业务考核结果 | 业务考核等级 | 枚举 | 合格、不及格 |
| 人才盘点结果 | 人才盘点等级 | 枚举 | S、A、B、C、D |
| 员工档案 | 聘期内人才盘点2次C | 三态布尔 | 待更新、是、否 |
| 员工档案 | 聘期内人才盘点连续2次C | 三态布尔 | 待更新、是、否 |
| 员工档案 | 续聘前最近一次人才盘点为C级 | 三态布尔 | 待更新、是、否 |
| 员工档案 | 当前聘期内是否有正式晋升 | 三态布尔 | 待更新、是、否 |

### 5.4 规则输出

一个规则可配置多个输出定义。

| 输出类型 | 可配置内容 |
|---|---|
| KPI处理 | 是否扣分、扣分值、作用周期 |
| 奖励处理 | 限制内容、限制方式、限制时长 |
| 调薪限制 | 禁止或人工复核、限制时长 |
| 晋升限制 | 禁止或人工复核、限制时长 |
| 年终奖处理 | 无、取消、人工复核、作用年度 |
| 培训或调岗 | 培训、调岗、培训或调岗、人工处理事项 |
| 降薪处理 | 建议降薪或人工复核 |
| 合同处理 | 不续签、建议解除、即时解除建议 |

配置中心只保存这些输出定义。劳动关系、降薪、调岗等高影响事项在未来只能形成待决策事项，不由配置中心直接执行。

## 七、修订和发布机制

修订机制用于保证历史规则可解释，而不是增加日常操作负担。

- 新规则首先保存为草稿；
- 草稿可反复编辑；
- 已发布内容不可直接修改；
- 修改已发布规则时，系统自动复制出下一修订草稿；
- 新修订发布并生效后，旧修订进入历史；
- 未来员工限制记录应保存命中时的规则修订和配置快照。

列表不突出修订号，只在规则名称下、详情、发布确认和历史记录中展示。

## 八、发布校验

发布前校验：

- 规则名称、类别、部门和生效日期完整；
- 已选择有效字段；
- 运算符适配字段类型；
- 触发值属于字段合法值；
- 至少存在一个输出；
- 生效日期不晚于失效日期；
- 限制输出已配置期限或结束方式；
- 同范围内不存在完全重复的生效规则；
- 同一条件的输出和期限不存在明显冲突。

发布校验不扫描员工，不检查命中人数，不生成任何员工记录。

## 九、权限和审计

| 权限 | 能力 |
|---|---|
| 查看规则 | 查看列表、详情和历史 |
| 编辑规则 | 新建规则、编辑规则草稿，以及为已生效规则创建下一修订草稿 |
| 发布规则 | 发布、撤回待生效修订 |
| 停用规则 | 停止规则后续适用 |
| 管理字段目录 | 启用、停用和维护字段说明 |
| 查看审计日志 | 查看规则全部变更记录 |

审计动作包括创建、修改、复制、发布、撤回、停用、删除草稿和字段目录变更。

## 十、建议数据模型

### 10.1 `TalentRestrictionRule`

规则稳定身份：名称、类别、适用部门、当前状态、当前生效修订、创建人和创建时间。

### 10.2 `TalentRestrictionRuleRevision`

不可变修订内容：修订序号、状态、制度依据、生效期、优先级、修订说明、发布人和发布时间。

### 10.3 `TalentRuleFieldDefinition`

字段目录：显示名称、来源、类型、枚举值、可用运算符、责任模块和启用状态。

### 10.4 `TalentRestrictionRuleCondition`

触发条件：规则修订、字段目录、运算符和比较值。本阶段每个修订只允许一条条件。

### 10.5 `TalentRestrictionRuleOutput`

规则输出：输出类型、处理方式、数值、时长、时间单位、作用周期、参数和排序。

## 十三、总体完成标准

- 员工档案具备配置中心所需全部事实字段；
- 旧人才决策配置已彻底移除；
- 工作事故、KPI、业务考核和人才盘点配置保持独立；
- 用户通过业务名称选择字段，无需输入内部编码；
- 每条正式制度规则都能用“一个字段条件+多个输出”完整表达；
- 已发布规则不可直接修改且历史可追溯；
- 配置中心不承担数据聚合、规则执行或人才决策。
